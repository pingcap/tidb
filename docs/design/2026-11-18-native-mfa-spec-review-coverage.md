## 3. 整体设计形状和模块边界审核

- 状态：已完成。
- 核查 parser→executor→系统表→cache 与 server→session→privileges→LDAP 两条链。
- 使用原 JSON、原事务和一次 Auth；未引入通用认证工作流或新凭据服务。
- 检查 privilege 数据类型与 variable 纯 policy parser 的依赖方向；插件可用性检查置于 session 写入口以避免循环依赖。

## 4. 主执行流程审核

- 状态：已完成。
- 覆盖 CREATE、多账号 ALTER、双操作、SET PASSWORD、RENAME/DROP、SHOW、首次握手、change-user、RESET、迁移导出及 token 登录。
- 检查首因子成功到最终 OK 之间的身份、默认角色、资源组、沙箱和失败计数更新时点。
- 覆盖预提交回滚及提交后通知失败的不同结果；不把后者误写成回滚。

## 5. API、字段与命名审核

- 状态：已完成。
- 核对第 8 节接口标记、调用方、结果及错误处理；已收敛精确身份的 HasMultiFactorAuth 为纯 bool 查询，无 MFA/缺失账号保持旧行为。
- 字段覆盖第一 AuthOpt、后续创建项/操作项、四项 JSON 字段、只读因子列表、无效标记和失败计数标志。
- AuthConn 旧契约保持；新可选接口仅用于 MFA，MFAAuthError 在 session 最终错误出口产生，由 change-user 消费；Unwrap/Cause 保持错误类型与 SQL 码。
