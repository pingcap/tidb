# Generated TiDB collation data

These binary images are a mechanical, lossless conversion of TiDB's
Apache-2.0-licensed Go authorities:

- `pkg/util/collate/general_ci.go`
- `pkg/util/collate/ucadata/unicode_ci_data_generated.go`
- `pkg/util/collate/ucadata/unicode_0900_ai_ci_data_generated.go`
- `pkg/util/collate/gbk_chinese_ci_data.go`
- `pkg/util/collate/gb18030_weight.data`

They are generated by `../../scripts/generate_collation_data.py`. The generator
also checks UCA 4.0 against
`pkg/util/collate/ucadata/unicode_ci_data_original_test.go`, reproducing the
source data-equivalence gate, validates both long-rune maps, and checks the
exact GBK and GB18030 table dimensions. Regenerate and verify from the
repository root:

```sh
python3 rust/crates/tidb-datatype/scripts/generate_collation_data.py
python3 rust/crates/tidb-datatype/scripts/generate_collation_data.py --check
```

The Rust tests pin the byte lengths and SHA-256 digests. Do not edit the binary
images by hand.

The Go `ucaimpl` templates generate repeated collator plumbing. Rust replaces
that support generator with the single typed `UcaCursor` implementation in
`collation.rs`; there is no generated Rust implementation file to drift. The
Go `ucadata/generator` outputs and retained original UCA 4.0 fixture remain the
inputs checked by this Rust generator, so both Go generator paths have an
explicit executable equivalent rather than a copied second authority.
