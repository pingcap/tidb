# TiDB Rust protocol sources

`build.rs` compiles checked-in protobuf inputs with prost. TiPB declarations
come from the **complete upstream schemas**, selected by Go master, in
`proto/tipb/`. Do not edit these copies or restore local message/enum subsets.
`tipb-source.json` records the immutable TiDB revision, its TiPB version and
hashes of every module artifact, including generated Go sources, original
tests, fixtures and generation/build inputs. The `tipb.tici` protobuf package
is exposed as `tipb::tici` in Rust.

From the repository root, refresh and verify the source after fetching master:

```sh
python3 rust/scripts/sync-tipb.py --write --go-ref origin/master
python3 rust/scripts/sync-tipb.py
python3 -m unittest discover -s rust/scripts/tests -p test_tipb_sync.py
cargo test --locked --manifest-path rust/Cargo.toml -p tidb-proto
```

The check compares exact upstream input bytes **and file membership**, plus
the complete module inventory. It also rejects a different TiPB pin in a
locally available `origin/master`. Shallow checkouts without that ref still
verify against the recorded immutable module. Updating requires an explicit
Go revision; the integration branch's older `go.mod` is not the baseline.
`make lint` runs the source guard and its regression tests. Cargo builds use
only the checked-in schemas and do not run Go or fetch protobuf inputs.

The former `RegexpLikeSig` omission was one consequence of copying partial
schemas by hand. Comparing only declarations already present locally left
new upstream messages, fields and enum values invisible. Copying individual
enums did not fix that ownership problem. The complete source check now
rejects any missing, extra or modified schema, including imported options.
Rust wire tests preserve existing field presence and byte vectors; the
SPFresh suite translates every original `go-tipb/spfresh_test.go` test.
Protocol completeness does not claim SQL execution support for every message.

KV requests, region errors, region metadata, encryption metadata, coprocessor
and MPP contracts reuse the complete `kvrpcpb`, `errorpb`, `metapb`,
`encryptionpb`, `coprocessor` and `mpp` packages generated by the native client.
Their inputs live in `rust/third_party/tikv-client-rs/proto`; `extern_path`
keeps imported fields the same Rust types. The native generator uses Bytes
for all four fields declared as Go SharedBytes, retaining response-buffer
ownership without a separate TiDB schema. The complete source and artifact
[receipt](../../docs/shared-client-contracts-inventory.json) is checked by
`python3 rust/scripts/check-shared-client-proto.py` in `make lint`.
After publishing and synchronizing native changes, review and refresh it with
`python3 rust/scripts/check-shared-client-proto.py --write --go-ref origin/master`.
This check verifies every upstream schema/include byte and file membership,
the complete Go module inventory, native generated outputs and build inputs.
The separate gRPC Channelz schema remains owned by native transport.

Other local protocols remain dependency-closed projections and are separately
listed for review in the structural audit. These gates do not establish
completeness for PD, the local TiKV service, etcd or BR schemas.
