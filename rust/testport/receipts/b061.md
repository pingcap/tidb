## Crate-mapping note (as in b062)

The manifest maps this base package to crate `tidb-protocol`, but the Rust
transcreation of the unistore code lives in `tidb-unistore`; `tidb-protocol`
contains only MySQL packet framing and has no mockstore symbols. Following
the accepted b062 precedent, the mandated gate was run verbatim AND the
owning-crate gate alongside; both are reported below. Test-code edits are
confined to `rust/crates/tidb-unistore/src/tests_mockstore_part1_go_parity.rs`
(new) plus its `mod` registration in that crate's `src/lib.rs`, and this
receipt.

## Method note

Every checklist item below was re-derived from the Go SOURCE on
origin/master (test bodies, exercised functions, error values), not from
Rust-side claims. Spot-findings of the re-read:

- All four lockstore tests, `TestDeadlock`, and all 27 existing mvcc ports
  were re-checked line-by-line against master; none diverges.
- Three arms skipped by the landed mvcc ports ARE implemented on the ported
  store (`KvError::PrimaryMismatch` exists in `check_txn_status`; the
  pessimistic arm exists in `check_secondary_locks`; the min-commit-ts push
  admits later commits), so this batch adds three executable parity tests.
- DIVERGENCE FOUND: master's `normalizeMockPDAddrs` keeps unix-family
  endpoints (`pkg/util/service_url.go` accepts unix/unixs verbatim), so Go's
  `TestMockPDServiceDiscovery` pins 3 clients including
  `unix://localhost:m0`. The workspace helper `normalize_mock_pd_url`
  rejects them; its existing passing test pins only 2 clients. Production
  files are outside a testport batch's edit scope, so the master vectors are
  recorded as an `#[ignore]`d pin here.
