# Batch b018 — pkg/util/collate

## Scope note / crate mismatch

The batch assignment names `tidb-util` as the owning Rust crate, but
`pkg/util/collate` was transcreated into **`rust/crates/tidb-datatype`**
(`src/collation.rs`, `src/collation_tests.rs`, `src/collation_data/*`,
`benches/collate.rs`). `tidb-util` contains no collate implementation (only
dbterror error-code aliases such as `ERR_UNKNOWN_COLLATION`). All ports below
therefore live in and were gated with `tidb-datatype`. No edits outside the
collation tests/receipts were made.

### Re-derivation evidence (from origin/master source, not comments)

- `compareCommon` (collate.go:382) returns 0 on the first invalid UTF-8 byte;
  generated UCA compare loops (unicode_0400_ci_generated.go:34,
  unicode_0900_ai_ci_generated.go) do the same; `generalCICollator.KeyWithoutTrimRightSpace`
  (general_ci.go) and both UCA `KeyWithoutTrimRightSpace` implementations return
  the buffer accumulated so far (empty when invalid at start). This pins the
  Rust assertions `is_empty()` / `Ordering::Equal` in
  `test_campare_invalid_utf8_rune`.
- `truncateTailingSpace` (collate.go:272) applied as Preprocess for pad-space
  collations explains the `{"a", "a "}` row differences.
- `RewriteNewCollationIDIfNeeded`/`RestoreCollationIDIfNeeded` sign rules match
  collate.go:118/129.
- ucadata data images are hash-pinned against the Go-generated tables
  (`scripts/generate_collation_data.py --check`) inside
  `generated_images_have_source_pinned_lengths_and_hashes`.

No new gaps found; no `go-parity-gap` ignores needed.
