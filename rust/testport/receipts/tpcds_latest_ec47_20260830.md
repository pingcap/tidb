## Current Rust evidence and next package boundary

The focused Rust test
`tidb-executor::driver::tests::subqueries::plain_explain_evaluates_and_labels_an_uncorrelated_scalar_subquery`
still fails at the planner boundary with the same 1105 error. The relevant
Rust code is `rust/crates/tidb-planner/src/plan_builder.rs::lower_scalar_subqueries`
and `rust/crates/tidb-planner/src/expression_rewriter.rs::handle_scalar_subquery`.
The Go implementation evaluates an uncorrelated scalar once while preserving
the separate `ScalarSubQuery -> MaxOneRow` plan root and an outer
`ScalarQueryCol#N`; any Rust correction must retain both execution semantics
and explain shape. The existing Rust `FromScope::plan_columns` and
`SCALAR_QUERY_SCOPE` hooks are evidence for that boundary, but are not yet
wired for ordinary SELECT planning.

No production code was changed in this checkpoint. The next atomic behavior
unit should inventory the complete Go planner/executor package boundary before
implementing scalar-subquery lowering, then add a regression test, rebuild, and
rerun this full matrix. Physical-column resolution, retained lookup-reader
construction, Q41 semantics, and TiFlash/MPP task execution remain separate
open items.
