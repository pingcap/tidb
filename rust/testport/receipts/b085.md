## Why every port is a gap port

All 60 items drive statements through a testkit session: prepare/execute,
`planner.Optimize`, `@@last_plan_from_cache` / `@@last_plan_from_binding`,
`explain for connection`, bindings, resource groups, Domain StatsHandle
sync-load, or TiFlash replica metadata + explain goldens. The Rust rewrite
keeps plan-cache machinery inside the `tidb-session` crate
(`prepared_plan_cache.rs::stmt_cacheable`, `non_prepared_plan_cache.rs`) as
`pub(crate)` surfaces behind a session dispatch tier with a different key
design; the `tidb-planner` crate has neither a session/testkit stack,
`planner.Optimize`, an LRU plan cache, stats sync-load, nor MPP/TiFlash task
generation. All 56 non-benchmark tests are therefore documented `#[ignore]`
gap ports asserting nothing; no behavior was approximated. The two `TestMain`
bootstrap harnesses are recorded skipped-reason like crate precedent for
part7's item 405. The seven benchmarks keep Go's Benchmark name shape; see
the measurement note below about their actual gate behavior in this session's
nextest version (0.9.143). One candidate real surface was checked and
rejected: `rule.CollectDependingVirtualCols`
(`rule_collect_plan_stats.go:420`) has NO Rust port anywhere in the workspace
(verified by grep), and its data types (`tidb-model`'s `ColumnInfo.dependences`,
`is_virtual_generated()`) live in a different crate from any logic that would
consume them, so item 471 stays an honest gap rather than newly invented
production code.
