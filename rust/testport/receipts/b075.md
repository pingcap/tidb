## Follow-up: `GetTimeValue`

The Go build-context helper is now executable in Rust as
`tidb_expr::get_time_value`. It preserves the source type-switch boundary:
raw strings recognize the current timestamp/date and zero-date sentinels,
`String`/`Int`/`Null` AST nodes model parser-driver values, function calls
return uppercase clock markers, and unary expressions route through the
constant evaluator before numeric temporal parsing. Unknown AST forms retain
Go's zero datum (`NULL`), while parse failures return the existing temporal
error class. The temporary pre-fix worktree failed to compile the focused
carrier because no helper symbol existed; the active regression now passes.

The shared `IsValidCurrentTimestampExpr` predicate is also wired into both
Rust DDL owners: `tidb-exec::table_info_build` and
`tidb-executor::column_default`. This removes the former hand-rolled
`ON UPDATE` acceptance path (including bare column markers) while preserving
the parser's Go-compatible canonicalization of `NOW()`/`LOCALTIME()` aliases.
The focused DDL table-builder and validator regressions cover bare versus
explicit FSP, aliases, and non-function expressions.

The focused DDL regression was also run in a detached pre-fix worktree at
`9dffe78b1f`: `TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP` incorrectly returned
`Ok(…)` and the test failed. After the predicate wiring above, the same case
is refused and the active test passes.
