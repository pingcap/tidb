## Divergences measured while porting (each recorded on its ignored test)

1. Go's `checkIndexNeededInForeignKey` PKIsHandle escape
   (`pkg/ddl/foreign_key.go:459-464`) applies to the CHILD's own constraints
   too (`:472-479`); the tier's `check_index_needed` previously applied it
   only on the referred branch. This is now closed by the focused child-cover
   regression; both branches use the shared clustered-handle exemption.
2. Go's pk-flag guard lives inside `checkModifyTypes`
   (`pkg/ddl/modify_column.go:2262-2273`): an incompatible-but-reorg-able
   move (int → narrower mediumint) on a primary-key column is 8200 "this
   column has primary key flag". The tier's guard (`ddl/alter_table.rs`,
   behind `integer_type`) fires only for non-integer targets, so the move
   succeeds here; the same ladder's int→tinyint over a stored 222 (Go
   `[types:1265]Data truncated for column 'a', value is '222'`) also runs
   unrefused — the tier does no row validation on narrowing.
3. TRUNCATE of a referenced table has no referral check, and DROP of one
   renders the child-side 1451 text where Go renders 3730
   (`pkg/ddl/tests/fk/foreign_key_test.go:801-887`).
4. At the time of this b111 receipt, ALTER ADD FOREIGN KEY also lacked the
   parent-side index and self-reference checks. Those two owner checks are now
   closed by the follow-up receipt `ddl_foreign_key_alter_validation.md`;
   multi-action ALTER add-rollback atomicity is now staged and covered by
   `ddl_foreign_key_alter_atomicity.md`; partial-index predicate safety remains
   a measured divergence.
