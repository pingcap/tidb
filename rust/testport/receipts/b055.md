Gate: `cd rust && cargo nextest run --locked -p tidb-lexer -E 'not test(/bench/)' --no-fail-fast`

## Scope definition

Following b052/b053/b056: all `func Test*` under `pkg/parser/**` on
`origin/master` (322 after dropping `TestMain`), sorted by (file path, line
number), chunked into groups of 60; part5 = items 241–300. The batch is
entirely:

- `pkg/parser/parser_test.go` (60 tests: `TestSQLResult` … `TestExplainExplore`)

Each test body and the production code it exercises were read from
`origin/master` (`git show origin/master:pkg/parser/parser_test.go`, plus
`lexer.go` / `misc.go` / `yy_parser.go` / `parser.y` for the scanner and
`yySetOffset` contracts). The branch's possibly-stale `pkg/parser` copy was
not used as evidence.

All 60 Go tests drive `parser.Parse` / `ParseOneStmt` plus AST Restore or
field inspection. The yacc parser and AST live in `tidb-parser` / `tidb-ast`,
which depend on `tidb-lexer`, so this crate cannot depend back on them.
Statement-level assertions are therefore explicit `go-parity-gap` ignores.

Surfaces this crate *does* own, and that those Go tests exercise as lexical
preconditions, are pinned rather than approximated:

- keyword-table membership (`tokenMap` / `windowFuncTokenMap`)
- charset-introducer recognition (`underscoreCS`, including non-legacy `gbk`)
- ANSI_QUOTES identifier quoting
- string-literal unescaping (`LexLiteral` / `UnescapeChar`)
- user/system variable tokenization (`@@global.` / `@@session.` /
  `@@local.` / `@@instance.` prefixes, quoted bodies)
- `AS OF` two-word merge
- window-function keyword gating (`EnableWindowFunc`)
- `/*T![ttl] ... */` feature-ID allowlist
- integer classification of `18446744073709551612` (`u64` `IntLit` /
  `LiteralValue::UInt`, past-`u64` `DecLit`)
- statement-separator vs. semicolon-inside-string
- optimizer-hint retention after `CREATE`

No behavior was approximated to make a test pass.
