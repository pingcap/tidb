## Rust ownership and audit result

`rust/crates/tidb-naming` owns the package and is re-exported through
`tidb_util::naming`. `tidb-config` uses `CheckKeyspaceName`, and `tidb-session`
uses `Check`; both compile against the package authority. Repository ownership
metadata remains a Go-repository concern and needs no Rust runtime artifact.

The audit removed Rust-only public error getters, `Clone`/equality behavior,
the unsupported importer-name documentation claim, and the prior supplemental
boundary test. The pinned `TestScope` cases remain as `test_scope`.

Go `CheckWithMaxLen` accepts a signed `int` and compiles a generated regexp on
every call. Rust previously accepted `usize`, supported maxima above 1000, and
therefore returned normally where Go panics. A direct pinned-Go runtime probe
also established the less obvious negative case: `{0,-1}` is parsed as literal
pattern text, so `CheckWithMaxLen("a{0,-1}", -1)` succeeds while ordinary names
fail. Rust now uses the native signed-width integer, reproduces that literal
negative pattern, and emits Go's panic payload above the 1000-repeat limit. A
focused regression test protects this previously divergent behavior.
