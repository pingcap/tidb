## Scope definition

The batch range was derived the same way as adjacent parser batches: all 323
`func Test*` functions under `pkg/parser/**` at `origin/master`
(`fa2a89347ba4071a31f9c3525293af25f91570d9`), sorted by file path and line
number, then chunked in groups of 60. Part 2 is items 61–120:

- `pkg/parser/ast/dml_test.go` (5 tests)
- `pkg/parser/ast/expressions_test.go` (22)
- `pkg/parser/ast/flag_test.go` (2)
- `pkg/parser/ast/format_test.go` (1)
- `pkg/parser/ast/functions_test.go` (9)
- `pkg/parser/ast/misc_test.go` (13)
- `pkg/parser/ast/model_test.go` (2)
- `pkg/parser/ast/procedure_test.go` (5)
- `pkg/parser/ast/sem_test.go` (1)

Each test body and the production implementation it exercises were read from
`origin/master`, not from this branch. The range exercises AST Restore/Format,
Visitor traversal, expression flags, sensitive-text redaction, `CIStr`, stored
procedures, and SEM command classification. None of these APIs is exposed by
`tidb-lexer`. Rust's `tidb-ast` and `tidb-parser` crates both depend on
`tidb-lexer`, so this crate also cannot depend back on them. The tests are
therefore explicit ignored parity gaps; no lexer approximation or test-local
reimplementation was used.
