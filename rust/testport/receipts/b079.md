## Structural facts that shaped the ports

- Two DIFFERENT memo packages exist at master: the live `pkg/planner/memo`
  (whose plan-hash-shaped leaves `expr_iterator` / `group_expr` /
  `explore_mark` ARE transcreated in this crate and covered by earlier
  batches' `memo_group_source.rs` / `memo_expr_iterator_source.rs`) and the
  legacy `pkg/planner/cascades/memo`
  (`container/list` equivalence runs + fingerprint-keyed dedup maps +
  failpoint-guarded `Memo.Init`), which has NO transcreation. Part2's memo
  items target the LEGACY package; every one is therefore an anchored gap,
  never an approximation through the new-memo carriers.
- The only legacy-memo leaf this crate owns is the group-id counter
  (`memo_group_id.rs` mirrors `group_id_generator.go:27-30` incl. the uint64
  wrap), with `GroupIdGenerator::from_raw` added by its author specifically to
  reproduce the Go test's private-field pokes
  (group_id_generator_test.go:35-47).
- `pattern.rs::get_operand` classifies a typed `LogicalOperatorKind`
  descriptor instead of Go's concrete-plan type switch
  (`pkg/planner/cascades/pattern/pattern.go:127`), so `TestGetOperand` drives
  all fourteen source kinds through the classifier rather than constructing
  logical plans.
- `task.go` stack pool semantics are externalized in this crate:
  `TaskStack::new()` pins pool.New's cap-4 reservation (task.go:25-28,
  :84-87), reuse-without-clean is carried by reusing one instance with explicit
  len/capacity checkpoints, and `destroy()` retains allocation
  (task.go:43-49). Go runtime `unsafe.Sizeof` pins
  (task_test.go:45-59: pointer 8 B, slice header 24 B, interface slot 16 B)
  have no honest carrier over `Vec<Box<dyn StackTask>>` — kept as an
  `#[ignore]`.
- `hash_equaler_test.go` items 61-62 need nothing beyond the transcreated FNV
  primitives (`hash_equaler.rs`: absorb ^=v; *PRIME64, hash_bool 1/0,
  byte-length-framed strings); `TestStructType`'s cross-type Equal dispatch is
  reproduced over `dyn Any` downcasting to keep Go's type-assertion semantics
  (:76 fails on `*SB`) without inventing a hasher-side type tag.
- Book-driven golden suites (`stringer_suite`, `transformation_rules_suite`)
  plus the old optimizer phases (`optimize.go:119/:128/:221/:268/:358`),
  38 transformation-rule constructors, `Binder` (binder.go:148/:201/:270/:299)
  and live-session EXPLAIN comparisons are unported end-to-end; each gap
  cites its rule set or pipeline stage.
- Upstream self-skips were honored, not force-portied:
  `xf_decorrelate_apply_test.go:40` calls `t.Skip`
  ("XFDeCorrelateSimpleApply rule is not applied in the cascades optimizer
  fully").
