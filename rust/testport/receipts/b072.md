## Gaps (go-parity-gap ledger)

- go-parity-gap: UNIX_TIMESTAMP's `{Int(151113102019)}`, `{Real(151113102019)}`
  rows need types.ParseTimeFromNum's 12-digit YYMMDDHHMMSS reading
  (`1447410019`), its Decimal-scale-7 row needs fsp-7 half-up rounding
  (`...123457`), and `{'2017-00-02'}` needs the IgnoreZeroInDate month-zero
  reader that answers INT:0; all three readers are absent at this evaluator
  seam (comment inside unix_timestamp_value_table_under_utc).
- go-parity-gap: TIMESTAMPADD's `±10000*365 ∓ 1` MONTH amounts exceed this
  evaluator's unit-dispatch amount guard and fail outright where Go answers
  NULL; TIMESTAMP/ TIMESTAMPADD integer-date arguments share the compact
  reader gap above (timestamp_compact_numeric_rows ignored stub).
- go-parity-gap: MAKETIME Float-second rows expect MaxFsp six-digit durations;
  this renderer sizes fractions by written digits, and the unsigned-wrap
  CAST(-1 AS UNSIGNED) hours case needs the wrap Go applies
  (maketime_float_second_maxfsp_and_unsigned_cast_rows ignored stub).
- go-parity-gap: DATE_ADD/SUB with a TYPED DURATION first argument selects
  Go's duration-result signatures through argument FieldTypes; that seam is
  chunk-tier-only here, so TestDateArithFuncs' trailing duration-format block
  stays unproven (comment inside date_arith_day_month_year_overflow_tables).
- go-parity-gap: PERIOD_ADD/PERIOD_DIFF rejections surface as
  EvalError::Unsupported("invalid PERIOD_* period"), not Go's
  "[expression:1210]Incorrect arguments to period_diff" text (inline comment
  next to the passing rejection-shape assertions).
- go-parity-gap: TIDB_BOUNDED_STALENESS requires Go's injectSafeTS failpoint
  seam plus oracle.GoTimeToTS epoch arithmetic
  (`builtinTiDBBoundedStalenessSig`, builtin_time.go:7090); no equivalent
  exists (ignored stub).
- go-parity-gap: MockVecPlusIntParallel's enableAlloc buffer allocator race
  has no model (ignored stub); serial correctness pinned separately.
- go-parity-gap: FLOAT32 columnar storage (mysql.TypeFloat chunks) is not
  modeled; vector floats exist only as scalar datums (Float32ColVec stub).
- go-parity-gap: VecEvalBool/EvalBool selection machinery (selected/nulls
  buffers over expression conjunctions) and the rowBasedFilter vs
  vectorizedFilter harness are absent (two ignored stubs).
