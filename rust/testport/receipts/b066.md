## Structural facts that shaped the ports

- The aggregation package's DESCRIPTOR half is ported in
  `tidb-expr::aggregation`; its EVALUATOR half (`GetAggFunc` /
  `CreateContext` / `Update` / `GetResult`, `createDistinctChecker`) lives in
  `tidb-exec::aggregate::runtime` — outside this batch's gate scope, so the
  runtime-half rows are recorded as parity gaps in this crate.
- `agg_to_pb.go` is deliberately unported: `tidb-proto`'s select.proto
  projection carries none of the aggregate/window `ExprType` values.
- The internal cast dispatch rewrites CAST to per-signature function names
  (`cast_signed`, `cast_decimal`, ...); this batch drives each signature the
  same way Go's `TestCastFuncSig` constructs raw signature structs.
- Fixture note: Go builds "today at 12:59:59" temporals at test init. These
  Rust tables pin 2020-10-10 10:10:10 and pin the statement clock through a
  fixed-clock context, so Duration-mixing rows stay deterministic. Each
  assertion keeps Go's INVARIANT (e.g. duration→time keeps the duration's
  clock; time→duration keeps the datetime's clock) rather than Go's literal
  clock value.
