(10 runnable tests + 49 `#[ignore]` go-parity-gap markers). No production
code was touched.

Key re-derived facts:

- The i64 returned through the failed-duration SQL port is *seconds*
  (`TIMESTAMPDIFF(SECOND, ...)`), converted by
  `last_failed_analysis_duration_from_seconds`; mocks feed seconds.
- Go's exact fail reason `"last failed analysis duration is less than 2 times
  the average analysis duration"` matches the Rust string byte-for-byte and is
  asserted directly.
- Divergence found: for the no-average case Go renders the bound via
  `time.Duration.String()` → `"less than 30m0s"`; the Rust
  `valid_to_analyze` hardcodes `"less than 30m"`. Not approximated: the
  runnable test pins the stable prefix only, and a dedicated `#[ignore]` test
  (`validate_and_prepare_only_failed_records_exact_go_fail_reason`) records
  the exact-string gap.
