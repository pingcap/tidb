## Gaps

- go-parity-gap: `TestJSONObject`'s `{1, true}` row needs a parser-originated
  BOOLEAN datum; Rust has no typed boolean `Datum`.
- go-parity-gap: `TestJSONSumCrc32` signed/unsigned ARRAY FieldType conversion
  and JSON-path extraction via `BuildJSONSumCrc32FunctionWithCheck` are not
  modeled on the value-only dispatcher.
- go-parity-gap: `TestJSONSchemaValidCache` uses a Go failpoint
  (`jsonSchemaValidDisableCacheRefresh`); Rust pins Clone-starts-empty instead.
- go-parity-gap: `TestTruncate` NaN rows require a session-created IEEE value
  the SQL constant parser cannot produce.
- Vectorized Go tests (`TestVectorizedBuiltin{Info,JSON,Like}Func`) have no
  `testVectorizedBuiltinFunc` harness; they are pinned through the rewritten
  scalar evaluator / dispatcher.
- Go `PbCode() == Clone().PbCode()` assertions have no Rust `PbCode` field on
  `ScalarFunction`; observable eval/clone contracts are pinned instead.
- Go `CURRENT_RESOURCE_GROUP` is in the vec-info case table but has no
  evaluator arm in Rust (`builtin_return_type` deliberately omits it).

No behavior was approximated to make a test pass.
