## Scope definition

The Go target is the Bazel-sharded `pkg/parser/ast:ast_test` family; batch
parts follow the same deterministic chunking the adjacent `pkg/parser/ast`
batches used: all 127 `func Test*` functions under `pkg/parser/ast/` at
`origin/master`, sorted by (file path, line number), part boundaries at 60
and at the end of `procedure_test.go`. That makes:

- part1 = items 1–60 (`base_test.go` 5, `ddl_test.go` 32, first 23 of
  `dml_test.go`);
- **part2 = this batch**: last 5 of `dml_test.go`
  (`TestImportActions` … `TestImportIntoFromSelectInvalidStmt`),
  `expressions_test.go` (22), `flag_test.go` (2), `format_test.go` (1),
  `functions_test.go` (9), `misc_test.go` (13), `model_test.go` (2),
  `procedure_test.go` (5) = 59 tests;
- part3 = `sem_test.go` (3) + `stats_test.go` (3) + `util_test.go` (2) —
  already landed by batch b059.

Every test body was read from `origin/master` via `git show`, never from
this branch, and re-derived against the production code it exercises
(`pkg/parser/ast/dml.go`, `expressions.go`, `flag.go`, `functions.go`,
`misc.go`, `model.go`, `procedure.go`, `expressions_test.go`'s visitor,
plus the transcreated restore paths in `tidb-ast`). Where Go parses SQL and
restores an extracted subtree, this crate owns the AST state, so each case
constructs the typed node Go's parser would produce and asserts the same
restored text through `Expr::restore()` / `Stmt::restore()` / secure-text /
redaction APIs.

## Remaining ownership boundaries

- `TestImportIntoFromSelectInvalidStmt`, `TestProcedure`,
  `TestDDLVisitorCoverMisc`, `TestDMLVistorCover`, and `TestProcedureVisitor`
  are live in the actual `tidb-parser` owner; the AST-crate carriers remain
  ignored solely to preserve dependency direction.
- `TestConvert` and `TestChar` are now covered at their actual parser owner by
  `tidb-parser::parser_root_source::test_function_charset_arguments_match_ast_source`.
  The AST-crate carrier functions remain ignored only to preserve the
  dependency direction (`tidb-ast` cannot depend on `tidb-parser`).
- `TestAstFormat`'s three JSON-path rows are live in the parser owner;
  `tidb-ast`'s hand-built carrier remains narrow because JSON-path operands
  are parser-produced expression state.
- Non-ignored, documented structural divergences inside ported tests:
  marker-leaf visitor counting (Go's `checkExpr` injection; vestigial
  `PatternInExpr.Sel` absent in Rust), free-standing WhenClause pinning via
  minimal `Case`, `MaxValue` extraction via full ALTER TABLE text,
  order-by-ordinal as literal expr, `VALUES(col)` spelling, and
  `Aggregate`-name canonicalization at construction time matching the Go
  parser states.
