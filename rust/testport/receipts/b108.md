## Measured divergences pinned by running tests

Go's multi-schema combination refusals are job-BUILD-TIME and atomic
(`checkOperateSameColAndIdx`, `pkg/ddl/multi_schema_change.go:350`; error
template `pkg/util/dbterror/ddl_terror.go:45`, code 8200). This tier applies
one ALTER's action list in order (`ddl/alter_table.rs::run_alter_table_in`),
so every such statement observes a sequential outcome. All pinned as
measured in this session, with Go's expectation cited at each assertion:

- rename+add-same-name → 1060 (Go 8200); rename+add-after-old-name → 1091
  (Go 8200); drop+rename-same-column → 1054 (Go 8200);
  rename+index-old-name → 1091 (Go 8200).
- alter+drop / alter+rename / alter+modify same column → statement
  SUCCEEDS (Go 8200); nothing checks the combination.
- change+drop-same-column → 1091; change+add-same-name → 1060;
  change+index-old-name → 1091 (all Go 8200).
- drop-index+rename-same-index → 1176 (Go 8200);
  add+rename-to-new-name → 1061 (Go 8200); drop-column+rename-its-index →
  1176 where Go silently no-ops the rename (multi-schema rename runs after
  the column's covering index is already gone).
- alter-index combinations: visible-then-invisible applies BOTH (final
  invisible; Go 8200); drop+alter → 1176 (Go 8200); add+alter SUCCEEDS
  (Go answers 1176 because its resolution never sees the new index).
- expression-index arms: drop-column + expression-index over it → 1054
  (Go 8200, atomic); the dup-entry arm MATCHES Go's 1062, but sequentially
  the already-applied `c` and non-unique `idx1` remain (Go rolls the whole
  job back).
- drop-column `IF EXISTS` note text: this engine files the MySQL canonical
  1091 text `Can't DROP 'b'; check that column/key exists`
  (`drop_column_action`) where Go files `column b doesn't exist`
  (`column.go:260`); the drop-INDEX note text matches Go exactly
  (`index.go:2262` vs `indexes.rs::drop_index_from_table`).
- `modify column c2 int after id, modify column id int after c2` leaves
  column order `[c2, id, c1]` (measured sequential move semantics; Go's
  owner re-plans sub-job order and the Go test asserts only success).
