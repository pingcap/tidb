## Scope definition

The assigned range was derived from the 323 `func Test*` functions under
`pkg/parser/**` on `origin/master`, sorted by file path and line number and
chunked into groups of 60. Part 4 is items 181–240:

- `pkg/parser/lexer_test.go` (12 tests: `TestScanString` through `TestFeatureIDs`)
- `pkg/parser/main_test.go` (`TestMain`)
- `pkg/parser/mysql/const_test.go` (4 tests)
- `pkg/parser/mysql/error_test.go` (`TestSQLError`)
- `pkg/parser/mysql/privs_test.go` (5 tests)
- `pkg/parser/mysql/type_test.go` (`TestFlags`)
- `pkg/parser/opcode/opcode_test.go` (`TestT`)
- `pkg/parser/parser_test.go` (35 tests: `TestMaxParenthesesDepth` through `TestIndexHint`)

The Go tests and the exercised production implementations were read from
`origin/master` with `git show`, not from this branch's `pkg/parser` copy.
Lexer-owned behavior was re-derived from `pkg/parser/lexer.go` and
`pkg/parser/misc.go`: `Scanner.scan`, `scanString`, `Lex`, `LexLiteral`,
`isTokenIdentifier`, `startWithSlash`, `scanVersionDigits`, and
`scanFeatureIDs`. The Rust tests pin the corresponding `tidb-lexer`
`Lexer`, literal decoding, keyword tables, feature-ID handling, offsets,
SQL-mode handling, and optimizer-hint position behavior. MySQL constants and
helpers, opcode formatting, yacc parser behavior, AST restore, and parser
error wrapping are explicit gaps because those APIs are not owned or exposed
by `tidb-lexer`; no behavior was approximated.

Two Go `TestScanString` vectors contain isolated non-UTF-8 source bytes and
cannot be represented losslessly as a Rust `&str`; the remaining UTF-8 vectors,
including the `\\a\\x18èàø»\\x05` case, are pinned.
