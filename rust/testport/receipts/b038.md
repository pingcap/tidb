# testport batch b038 — pkg/util/codec → tidb-codec

Gate: `cargo nextest run --locked -p tidb-codec --no-fail-fast`

## Scope

All 38 `func Test*` functions across `pkg/util/codec/{codec,bytes,decimal,collation,bench}_test.go`
were read from `origin/master` and cross-checked against the existing Rust
tests in `rust/crates/tidb-codec/src/tests/` (which already pin several of
these Go tests under source-derived names). New ports live in
`rust/crates/tidb-codec/src/tests/go_codec_port.rs`.

Notes on deliberate port-level adaptations (behavior-preserving):

- Go datum-construction coercions (`bool → int64`, binary literal / enum /
  set → `uint64` on decode) are asserted at the post-coercion point, since
  Rust datums carry the typed values directly.
- Go's `SetLength(30)/SetFrac(6)` decimal normalization maps to
  `Decimal::with_declared_shape(30, 6)`; `SetLength(20)/SetFrac(6)` to
  `encode_decimal_fixed(_, _, 20, 6)`.
- Chunk-dependent tests are ported over the equivalent row/datum seams
  (`hash_row`, `equal_rows`, `hash_column`, `decode_one_typed`) — the crate
  has no Go-chunk dependency.
- `TestEncoderNewCollationEnabled`: Go toggles a process-global flag; the Rust
  encoder carries the mode explicitly (`Encoder::new(true/false)`), so both
  modes plus the exported default-tracking `encode_key` are asserted directly.
- `TestDatumHashEquals` drives `planner/cascades/base.NewHashEqualer` (outside
  this crate); the port asserts byte equality of the codec-side lossless
  `HashCode` payload that such a hasher consumes.
