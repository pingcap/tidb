## Integration decision

The Go package maps to the scalar/key codec modules in `tidb-codec`. Go's
`MyDecimal` physical representation and global collation switch are owned by
`tidb-datatype`, so the package fix crosses that crate boundary. Chunk-based Go
entry points use Rust rows of `Datum`; this changes container ownership, not
the emitted key/hash bytes, null markers, selection behavior, or errors.

Rust now uses one `DecodeRange` entry point with optional index types, matching
Go's nil/non-nil `idxColumnTypes` branches. Go-private peek and value-size
helpers are crate-private. The Rust-only decimal metadata inspector, cache-like
decimal failpoint API, and their tests were removed.

## Behavior closed in this audit

- permissive `CutOne` byte framing and truncated-varint length behavior;
- the single-byte comparable-varint remainder returned by Go;
- DATE/DATETIME/TIMESTAMP/FLOAT restoration in `DecodeRange`;
- signed unspecified decimal metadata in group hashing;
- UTC timestamp conversion guard;
- physical negative-zero decode/re-encode and low-81-digit decimal retention;
- decimal header/size/panic edges, scale clamping, value-size behavior, and
  signed invalid-shape partial header writes;
- Go's initial enabled collation mode and exported encoder dependence on the
  mutable process mode;
- unsigned integer hash tags and collation-aware group/row/column keys.
