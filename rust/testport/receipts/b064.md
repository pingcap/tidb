## Crate-mapping note

The manifest maps base package `pkg/distsql` to crate `tidb-distsql`. The
subpackage `pkg/distsql/context` (its only test is `TestContextDetach`) maps to
the same crate's `DistSqlContext` (`src/context.rs`), whose detach semantics
were already pinned in `src/tests.rs`; nothing outside that module had to be
touched for the batch. All edits this batch are confined to three new files,
`rust/crates/tidb-distsql/tests/{range_encoding_literals_source.rs,
mock_response_iteration_source.rs, select_result_gaps_source.rs}`, plus this
receipt; no production code changed.

## Method note

Every pre-existing Rust counterpart listed below was re-derived line-by-line
against `git show origin/master:<file>` sources (each Go test plus the
functions it exercises: `pkg/distsql/request_builder.go`, `distsql.go`,
`select_result.go`). Where an existing port pinned less than the Go test does,
this batch added complementary `#[test]` functions instead of editing the
pre-existing files, so one directory keeps the whole package-level obligation.

Two deliberate divergences observed while re-deriving, recorded rather than
"fixed":

1. `SelectResponseIter` installs every output channel of a response and drains
   them in Go's reverse-priority order; Go instead lets callers hand-select a
   channel through `newSelRespChannelIter(result, channel)`
   (`pkg/distsql/select_result.go:829`). Observable sequences agree, so the
   ported tests assert sequences, not iterator internals.
2. `ResponseChannelError::IntermediateOutputCount` renders lower-cased —
   `the length of intermediate output types N mismatches …`
   (`src/response_channel.rs`) — where Go's runtime error reads
   "The length of intermediate output types %d mismatches…"
   (`pkg/distsql/select_result.go:455`). Existing tests pin the variant, not
   the casing; callers do not substring-match it today.

### go-parity-gap notes

1. **TestSelectResultRuntimeStats** (`#[ignore]`
   `select_result_runtime_stats_string_composition_is_unported`): Go composes
   `selectResultRuntimeStats.String()` — tikv `RegionRequestRuntimeStats`
   counters (`cop_task: {…}`, rpc_info/rpc_errors), percentile cop-resp /
   proc-keys histograms, duration formatting, and String-idempotence
   (`pkg/distsql/select_result.go`, `tikv` RegionRequestRuntimeStats). The
   transcreated accumulator (`src/distsql_runtime.rs::
   SelectResultRuntimeStats`) owns only backoff totals and checked tipb
   execution summaries; formatted stat strings never existed in this crate,
   and approximating the expected strings would violate the no-approximation
   rule.
2. **TestSelectResultIter closing block** (`#[ignore]`
   `select_next_rejects_intermediate_output_responses_structurally`): Go
   returns "selectResult is invalid after IntoIter()" from NextRaw/Next/
   IntoIter/Close (`select_result.go:501,530,544,771`) and refuses consuming
   Next over intermediate-output responses
   (`select_result.go:455 "If a response contains intermediate outputs, you
   should use the SelectResultIter to read the data"`). The Rust boundary
   removes the hazard by moving response ownership into
   `QuerySelectResult::into_select_iter`, so the misuse cannot be expressed;
   there is no runtime rejection to assert until a non-consuming read path is
   added.
