Notes:

- The crate convention is inline `#[cfg(test)] mod tests` inside each source
  module (`rust/crates/tidb-util/src/disjointset/set.rs`,
  `.../disjointset/int_set.rs`); no sibling `tests_*.rs` modules exist in this
  crate, so the ports live there.
- `TestDisjointSet` asserts on the internal `parent` vector length after each
  union/lookup; the Rust port mirrors this against `Set::parent` directly,
  matching the Go source semantics of `NewSet`/`InSameGroup`/`Union`
  (missing values inserted as singletons).
- `TestIntDisjointSet` checks initial parent identity `parent[i] == i` for
  `NewIntSet(10)` and root equality after 7 unions; ported as
  `test_int_disjoint_set`. Note the Go `IntSet.union` makes `b`'s root win;
  the Rust `SimpleIntSet::union` matches (`parent[root_a] = root_b`), and the
  assertions only compare roots pairwise, so they hold either way.
- Extra boundary tests already present in both modules exercise
  `find_root`/`find_value` (sparse) and `clear`/`grow_new_int_set` (dense),
  which Go master exercises indirectly via planner callers.

No `go-parity-gap` items.
