## Why every item is a documentary port

All sixty Go entries are execution benchmarks requiring a live session:
`runBenchmark` (:294) boots the mock store + domain (`prepareBenchSession`
:72), DDLs the scheme-partitioned table with per-access fixtures
(`preparePointGet` :196 five rows; `prepareIndexLookup` :218 /
`prepareTableScan` :224 both feeding `insert1kRows` :203 → 1024 rows), runs
`analyze table t`, then `runPointSelect` (:122) asserts `explain <query>`'s
first row starts with the expected operator (strings.HasPrefix :166) and counts
`FoundInPlanCache` hits (:160, :182-183) across the timed loop. Three
load-bearing behaviors are recorded:

1. For every partitioned scheme the batch-IN query expects `TableReader`,
   not `Batch_Point_Get` — :248-252 comment "Batch_Point_Get is not yet
   enabled for partitioned tables!".
2. `expectHits` (:160) counts cache hits only for IndexLookUp/TableReader;
   [Batch]PointGet never registers hits ("already using the FastPlan" :159).
3. `getListPartitionDef` (:516-538) generates p0=values in (1..256),
   p1=(5000..5255 **plus value 0** via the `expr != "" && i == 1` branch
   :528-531, which fires for BOTH "id" and "floor(id*0.5)*2" call sites),
   p2=(10000..10255), p3=(99900..100155).

The `tidb-planner` crate has no session/executor/plan-cache layer (no
`FoundInPlanCache`, no mock-store bootstrap; local
`access_path::PointGetAdmission` is only a pass-through marker enum). No Rust
surface exists for these contracts and none was approximated; each port keeps
Go's `Benchmark…` name shape so the gate filter `not test(/bench/)` excludes it
exactly as `go test` skips Benchmarks. Verify existence separately with
`-E 'test(tests_partition_scheme_plan_cache_benchmarks_source)' --run-ignored
only` → 60/60 pass (empty documentary bodies). Port file:
`rust/crates/tidb-planner/tests/tests_partition_scheme_plan_cache_benchmarks_source.rs`.
