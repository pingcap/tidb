## Why the ports are shaped this way

Fifty-three of the sixty items are prepared-plan-cache execution benchmarks or
looped multi-statement benchmarks driven through mock-store sessions
(`prepareBenchSession` :72, `runPreparedPointSelect` :852,
`benchPreparedPointGet` :898, `runBenchmarkPrepared` :958,
`BenchmarkHashPartitionMultiPointSelect` :1440). They need PrepareStmt /
ExecutePreparedStmt over a live session plus `FoundInPlanCache` counting —
outside the crate surface, matching the boundary recorded by receipts
b083/b084/b092/b095/b097 for neighboring planner parts — so they are
documentary `#[ignore]` ports whose names keep Go's `Benchmark` shape and are
therefore excluded by the gate filter `not test(/bench/)` exactly as `go test`
skips Benchmarks. `:1482 TestBenchDaily` registers a subset of those same
non-prepared families with `benchdaily.Run` for nightly CI and contains no
assertion of its own; it has no Rust counterpart to call.

`main_test.go:25 TestMain` is bootstrap-only (goleak filters +
SetupForCommonTest) and is recorded skipped-reason per crate precedent; it has
no Rust test.

One item carries a REAL running port. `point_get_plan_test.go:277
TestPointGetId` pins that the plan-id counter restarts before every top-level
build (`planner.Optimize` twice yields `p.ID() == 1`). The resets live at
`buildLogicalPlan` (`pkg/planner/optimize.go:904`,
`sctx.GetSessionVars().PlanID.Store(0)` before `builder.Build`) and again in
`TryFastPlan` (`pkg/planner/core/point_get_plan.go:97`) before the fast-path
conversion that decides the query. This crate models that counter explicitly as
[`PlanIdAllocator`] (`src/plan_base.rs`: fresh allocator hands out 1,
monotonic thereafter, consumed once per statement build) because no session
owns it yet. The running test pins the equivalent observable at that seam:
two independent `build_select("select c2 from t where c1 = 1")` passes over
`t (c1 int primary key, c2 int)` allocate identical sorted id sets starting at
1, ids are unique inside a pass, and a SHARED allocator provably never
restarts (root id of pass two > 1) — the exact regression the Go-side resets
prevent. The pipeline tail that has no Rust owner (session Parse/Preprocess/
Optimize ending in a PhysicalPointGet carrying `ID()==1`) stays a separate
documentary `#[ignore]` twin; nothing is approximated into passing.
