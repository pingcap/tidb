## Rust ownership and audit result

`rust/crates/tidb-util/src/encrypt/{aes,aes_layer,crypt}.rs` owns production
behavior and the seventeen source-named tests. `rust/crates/tidb-util/src/encrypt/mod.rs`
owns the public module boundary, and `rust/crates/tidb-util/benches/encrypt.rs`
owns the source benchmark. Live consumers are the expression crypto builtins,
checksum composition, and plaintext/encrypted chunk spill stacks.

The earlier audit had already removed the public export of Go's private block
size, equality/cloning from the error representation, and a Rust-only negative
offset refusal. This audit found and fixed three remaining source differences:

- writer cache offsets and positional-reader cursors now use explicit wrapping
  arithmetic, matching Go `int64` instead of panicking in debug builds;
- `pkcs7_unpad` returns a borrowed prefix of its input, matching Go's returned
  subslice instead of allocating a separate vector;
- invalid IVs panic with the constructor-specific Go 1.25.10 sentinel,
  including the AES-optimized CTR path's `bad IV length` value.

The `testexport` deterministic CTR constructor remains excluded from default
production builds. It is the Rust cross-crate equivalent of same-package test
access and exists only so chunk tests can replay Go-generated encrypted spill
bytes; removing it would remove parity evidence rather than production
behavior.

The seventeen source behavior tests remain with no Rust-only test cases or
assertions. The Go `TestMain` leak harness has no Rust runtime analogue because
this package creates no background worker. The current-master source delta is
empty, so this re-audit required no new code fix or regression test.
