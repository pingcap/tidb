# b021 — port `pkg/util/encrypt` Go unit tests to `tidb-util`

Go code: pkg/util/encrypt (aes_test.go, aes_layer_test.go, crypt_test.go,
main_test.go).

All 18 Go test functions were found already transcreated as in-module
`#[cfg(test)]` tests inside the owning modules of
`crates/tidb-util/src/encrypt/` (the crate's established convention for this
package — `mod tests` siblings inside each source module, Go test names
preserved, `#![allow(non_snake_case)]`). This batch verified each Rust test
against its Go counterpart on `origin/master`, case by case, rather than
duplicating infrastructure:

- `encrypt/aes.rs::tests` — covers all of aes_test.go including every invalid
  PKCS#7 unpad case, NIST SP 800-38A ECB vectors, all mode encrypt/decrypt
  tables (ECB/CBC/OFB/CTR/CFB) with negative key-length and bad-padding cases,
  and DeriveKeyMySQL vectors.
- `encrypt/crypt.rs::tests` — covers crypt_test.go TestSQLDecode /
  TestSQLEncode with the full golden table (incl. multi-byte strings).
- `encrypt/aes_layer.rs::tests::TestReadAt` — covers all four layering
  combinations from aes_layer_test.go (plain, checksum-over-encrypt,
  encrypt-over-checksum, double encryption) using an in-memory file instead of
  a temp file; asserts n, content (with zero-fill past EOF) and EOF semantics.
- main_test.go `TestMain` is goleak verification only; no Rust analogue is
  needed (documented in `crates/tidb-util/src/encrypt/mod.rs`).
- `BenchmarkReadAt` / `BenchmarkSQLDecode`-style benchmarks are out of scope
  for unit-test porting.

No new test code was required; no behavior gaps were found.
