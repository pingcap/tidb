Notes:
- Go's `BenchmarkReadAt` is a benchmark, not a unit test; the crate already has
  a non-harness `encrypt` criterion bench and it was not duplicated.
- Go's `main_test.go` only installs `goleak.VerifyTestMain`; no runtime
  analogue in Rust (documented in `encrypt/mod.rs`).
- An in-crate port of `TestReadAt` also exists at
  `encrypt::aes_layer::tests::TestReadAt` using a memory file; the port above
  re-proves it over real files exactly as Go does.

## Ignored gaps

- `tests_encrypt::aes_ecb_vectors` — go-parity-gap: Go's test drives the
  package-private raw ECB mode (`newECBEncrypter`/`newECBDecrypter`, no
  PKCS#7 framing); `tidb_util::encrypt` exports only padding-wrapped
  `aes_encrypt_with_ecb`/`aes_decrypt_with_ecb`, and the raw helpers
  (`ecb_encrypt_raw`) are `pub(super)` + `#[cfg(test)]`. Batch edit scope did
  not permit widening `encrypt/mod.rs` exports.
