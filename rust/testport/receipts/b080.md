## Re-derivation notes

### The two real ports (items 121–122)

Both loops in task_test.go drive exactly one behavior: a stack created with
capacity 1000 (`task.go:84 newTaskStackWithCap`; Rust `TaskStack::
with_capacity`) is filled with 1000 numbered tasks (`Push`, task.go:74) and
drained (`Pop`, task.go:64 removes the tail; nil once `Empty`, task.go:79).
The Go cost comments (24000 B/op steady state) imply draining neither grows
nor shrinks the backing array, so the Rust ports assert capacity retention
across two fills. The interface variant additionally routes descriptions
through dynamic dispatch (`Box<dyn StackTask>` mirrors `[]base.Task`),
pinning `Stack.Desc`'s (task.go:51) bottom-to-top, newline-per-task text.
`TestTaskImpl.Desc` writes `strconv.Itoa(a)` (task_test.go:35), mirrored as
plain integer `to_string`. The sibling unit tests TestTaskStack /
TestTaskFunctionality (task_test.go:39/:55) belong to part2 and are NOT
re-covered here beyond what the benchmark bodies themselves exercise.

Everything else is a `#[ignore]`d documentary test whose doc comment cites
its Go symbol and re-derived contract; bodies stay EMPTY because asserting
them would require inventing behavior the crate does not have ("never
approximate"). Family-level machinery named in each gap:

- All 8 non-stack families need a live TiDB via `testkit`
  (`CreateMockStore`, `RunTestUnderCascades[_WithDomain]`) or
  `planner.Optimize` over a session. `tidb-planner` contains planner
  primitives only; there is no session, executor, statistics handle,
  domain, or EXPLAIN-printer for whole plans behind it.
- Golden books consumed by these suites (binary_plan_suite,
  cascades_suite, cascades_template, analyze_suite, ch_suite,
  correlated_subquery_suite, plan_suite, enforce_mpp_suite) were not
  ported: recording their json/txt outputs against an optimizer that does
  not exist would fabricate fixtures rather than pin behavior.
