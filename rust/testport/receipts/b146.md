## Port status

All 60 functions are represented one-to-one as explicit `#[ignore]` Rust
carriers. None is claimed as runnable parity. This is intentional:

- bootstrap and upgrade cases require Go `session.BootstrapSession`, Domain,
  storage transactions, `meta.Mutator.FinishBootstrap`, versioned
  `upgradeToVer*` functions, DDL jobs, failpoints, cluster upgrade handlers,
  system-table metadata, and distributed-task state;
- clustered-index cases require Go transaction snapshot/cache inspection,
  TiKV-backed row encoding, old-row-format session state, and clustered
  partition DML;
- common cases require Go session protocol metadata (`LastInsertID`,
  `AffectedRows`, last message, query string, client capability), Go testkit
  prepared-session APIs, and Go table metadata;
- prepare-dedup cases require the Go `PlanCacheStmt` prepare dedup cache,
  schema-version invalidation, database-scoped cache keys, and the
  prepare/execute/close lifecycle; and
- `TestMain` functions are Go process/common-test/goleak harnesses, not
  behavior tests exposed by the Rust session API.

Every carrier has a `go-parity-gap` reason and a source citation to the Go test
function plus the relevant production seam. No behavior was approximated.
