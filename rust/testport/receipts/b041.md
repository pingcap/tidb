# testport batch b041 — pkg/meta (part3) → tidb-meta

Gate: `cargo nextest run --locked -p tidb-meta --no-fail-fast` (run from `rust/`).

## Scope

Tail slice of Go `pkg/meta/meta_test.go` on `origin/master` ("pkg/meta.part3",
the last ~10 test/benchmark items of the file): both benchmark bodies
(`BenchmarkIsTableInfoMustLoad`, `BenchmarkTableNameInfo`, including their
`benchCases` narrow/wide table shapes), the four small tests at the end of the
file, and the three InfoSchemaV2 bootstrap tests. The earlier slices of
`meta_test.go` were already ported by batch b039 (`rust/testport/receipts/b039.md`);
this batch re-derived every item below against `origin/master:pkg/meta/meta.go`
/ `meta_autoid.go` / `transaction_rules` equivalents and added one new Rust
test module,
`rust/crates/tidb-meta/tests/meta_test_part3_go_parity.rs`
(auto-aggregated into the `all` integration-test target by
`scripts/aggregate-tests.rs`; no lib.rs/mod registration needed).

Note: Go's `benchIsTableInfoMustLoad` builds payloads via
`ddl.MockTableInfo(parser.ParseOneStmt(sql))`; the Rust crate has no DDL
mock-table pipeline, so the same narrow/wide TableInfo values are constructed
directly and serialized with the crate's Go-compatible marshaller
(`value::serialize_table_info`). The asserted property is exactly Go's
in-loop assertion: a fully populated ordinary table is NOT "must load", and
both name-info decoders read ID=1 / Name.L="t" from it.
