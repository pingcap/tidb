Notes:
- All 8 tests from `fd_graph_test.go` were already transcreated as the in-module
  `#[cfg(test)] mod tests` of `crates/tidb-funcdep/src/fd_graph.rs`; this batch
  re-derived each against `origin/master` and confirmed assertion parity
  (same inputs/expected FD strings). No changes were needed to them.
- The 3 tests in `extract_fd_test.go` are end-to-end planner tests
  (mock store → parse → preprocess → build → `LogicalOptimizeTest` →
  `LogicalPlan.ExtractFD()` → golden `FDToString`). The Rust planner's
  `extract_fd` is an explicit stub
  (`crates/tidb-planner/src/logical/mod.rs`, `pub const fn extract_fd(&self) {}`),
  and no SQL pipeline exists inside `tidb-funcdep`. They are ported as
  `#[ignore]` stubs with `go-parity-gap` reasons in
  `crates/tidb-funcdep/src/tests_extract_fd.rs`; hand-built FdSet inputs would
  have asserted our own derivation rather than Go's pipeline.
- `main_test.go` is testkit bootstrap only — nothing to port.
