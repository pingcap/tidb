## Scope

Middle slice of Go `pkg/meta/meta_test.go` on `origin/master`
("pkg/meta.part2", 60 inventory items). A coverage audit against the
already-landed part1 (`rust/testport/receipts/b039.md`) and part3
(`rust/testport/receipts/b041.md`) batches showed every `func Test*` of this
slice was already translated in
`rust/crates/tidb-meta/tests/{transaction_source,key_prefix_and_element_source,iter_databases_source}.rs`.
The only unpinned items in this slice were the two global-ID benchmark bodies
(`BenchmarkGenGlobalIDs`, `BenchmarkGenGlobalIDOneByOne`), which this batch
ports as correctness assertions in a new module
`rust/crates/tidb-meta/tests/meta_test_part2_go_parity.rs`
(auto-aggregated into the `all` integration target; no mod registration
needed). Each ported item below was re-derived against
`origin/master:pkg/meta/meta.go` / `meta_autoid.go` / `element.go`.

## Not verified locally

- Go's benchmark throughput semantics (timing) are intentionally not
  asserted; only each loop's final-state assertion is pinned.
- The Go benchmarks run against unistore-backed mockstore transactions that
  are rolled back; the Rust ports use `MemoryTransaction` without commit,
  which is this crate's equivalent in-memory boundary. Persistence across a
  real commit boundary is covered by other existing tests, not re-pinned here.
