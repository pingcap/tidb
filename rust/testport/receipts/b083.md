## Re-derivation notes for the running ports

Both running tests are re-derived from the SQL bodies, not assumed:

- The unsigned-promotion arm builds `SELECT c1 FROM t1 UNION ALL SELECT c1
  FROM t2` against catalog tables typed exactly like the Go CREATE TABLEs
  (`logical_plan_builder_test.go:64-66`: `int`, `int unsigned`,
  `bigint unsigned`). Go's answer comes from `buildProjection4Union`
  (`pkg/planner/core/logical_plan_builder.go:2053`) folding branch types via
  `unionJoinFieldType` (:2001) = `types.AggFieldType`
  (`pkg/types/field_type.go:63`): mergeFieldType(Long, Long) stays TypeLong,
  mixed signs plus an unsigned member equal to the current type bump it to
  TypeLonglong. This crate's owners of those lines are
  `tidb-planner/src/plan_builder/set_opr.rs`
  (`build_projection4_union`, `union_join_field_type`) and
  `tidb-datatype/src/field_type/aggregate.rs` (`agg_field_type`), so the test
  asserts `FieldTypeCode::LongLong` on column 0 of the built LogicalUnionAll's
  schema — the same observable Go reads through `rs.Fields()[0]`.
- The decimal arm relies on the literal `0` being a signed TypeLonglong by
  `types.DefaultTypeForValue` (Rust:
  `tidb-expr/src/rewriter/result_type.rs::int_literal_type`, LongLong flen =
  printed digits), so AggFieldType bumps TypeLonglong → TypeNewDecimal;
  asserted as `FieldTypeCode::NewDecimal`. Both promoted expectations match
  the Go comments at logical_plan_builder_test.go:73/79 verbatim.
