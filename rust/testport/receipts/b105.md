## Test modules (all new, all under `rust/crates/tidb-executor/tests/`)

The crate aggregates every `tests/*.rs` via `scripts/aggregate-tests.rs`, so
adding files is the whole registration. Go's tests drive the online-DDL job
queue with concurrent sessions and failpoints; this tier has no job queue, so
each port pins the serialized end-state contract and the un-implementable
halves are `#[ignore]`d documentaries citing the Go file:line. Divergences
found while porting are documented in the test comments and below — never
papered over.

## Captured divergences (documented, not asserted)

1. ALTER ADD FOREIGN KEY auto-creates the covering index; Go refuses with
   "Failed to add the foreign key constraint. Missing index for '%s' foreign
   key columns in the table '%s'" (pkg/ddl/foreign_key.go:664).
2. FK violation messages omit the rendered action suffix ("ON DELETE
   CASCADE") Go's planner appends (1452/1451).
3. CHANGE COLUMN does not resolve a constraint's referenced table, so Go's
   1146 for a missing parent is not reproducible.
4. TRUNCATE TABLE has no 1701 FK referral check; DROP TABLE of a referenced
   table renders 1451-shaped text where Go reuses 1701
   (pkg/ddl/foreign_key.go:404).
5. DROP DATABASE performs no cross-schema FK referral check (Go 3730).
6. None. Anonymous index generation now follows Go's collision loop,
   including c1_2, c1_4, and primary_3 on ALTER adds.
7. Multi-spec ALTER TABLE is not atomic: `drop index i1, drop index i3`
   drops i1 before failing 1091 on i3 (Go leaves i1 in place).
8. Duplicate index drops report 1091 where Go refuses 8200
   ErrUnsupportedDDLOperation.
9. The GLOBAL index option is not honored on ADD INDEX (behaves as if
   absent, firing the 8264-style error).
10. ALTER ADD/DROP PRIMARY KEY is unsupported in this tier.
