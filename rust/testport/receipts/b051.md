# testport batch b051 — pkg/parser (part1) → tidb-lexer

Gate: `cd rust && cargo nextest run --locked -p tidb-lexer -E 'not test(/bench/)' --no-fail-fast`

## Scope definition

The batch range was derived the same way as adjacent parser batches: all 323
`func Test*` functions under `pkg/parser/**` at `origin/master`, sorted by
file path and line number, then chunked in groups of 60. Part 1 is items 1–60:

- `pkg/parser/ast/base_test.go` (5 tests)
- `pkg/parser/ast/ddl_test.go` (32)
- `pkg/parser/ast/dml_test.go` (23; through `TestLoadDataRestore`)

Each test body and the production implementation it exercises were read from
`origin/master`, not from this branch:

- `TestNodeSetText` / the four `TestBinaryStringLiteral*` cases call
  `(*node).SetText`, `Text`, `OriginalText`, `SetNoBackslashEscapes`, and
  `convertBinaryStringLiterals` in `pkg/parser/ast/base.go` (charset
  `Encoding.Transform`, comment skipping, GBK trail-byte handling, hex
  encoding of non-printable quoted strings).
- `TestDDLVisitorCover` / `TestDMLVisitorCover` construct AST nodes and
  drive `Accept` with `checkVisitor`/`visitor1`.
- Every remaining test calls `runNodeRestoreTest` /
  `runNodeRestoreTestWithFlags` / `runNodeRestoreTestWithFlagsStmtChange`
  to parse SQL and Restore a extracted AST subtree (DDL column/index/
  constraint/alter/sequence/placement/TTL/resource-group, DML table-name/
  join/window/LOAD DATA, etc.).

None of these APIs is exposed by `tidb-lexer`. Rust's `tidb-ast` and
`tidb-parser` crates both depend on `tidb-lexer`, so this crate also
cannot depend back on them. The tests are therefore explicit ignored
parity gaps; no lexer approximation or test-local reimplementation was
used. (Feature-id allowlists such as `placement`/`ttl`/`pre_split` are
owned by this crate's `can_parse_feature`, but these Go tests assert
parse+Restore wrapping, not the allowlist itself.)
