## Rust ownership and integration

The root data tree and package operations are in
`rust/crates/tidb-config/src/config_tree`, with the root package's standalone
files in `external_workload.rs`, `keyspace_observability.rs`, `store.rs`, and
`tiflash.rs`. The TiKV client-facing embedded configuration is in
`tikvcfg.rs`. Native Go `uint` fields use Rust `usize`; the required port type
change is propagated through `tidb-domain`, `tidb-server`, and `tidb-session`.

This audit filled the remaining root-package behavior:

- `InitializeConfig` loading/check/strict/warning flow, starter TLS environment
  overrides, temp-storage path refresh, global config publication, and derived
  TiKV global config publication;
- `CloneConf`, `ConfReloadFunc`, `RestoreFunc`, table-lock accessors,
  max-allowed-packet and transaction-scope accessors;
- `Security.ClusterSecurity`, `Log.ToLogConfig`, and
  `OpenTracing.ToTracingConfig` conversions;
- full `Config.Valid` ordering/mutation, including local-latch validation and
  persisted lowercase spill-encryption method;
- reflection-order `MergeConfigItems`, including Go field names, dynamic
  fields, maps, and fields hidden from JSON;
- exact 64-bit `uint` token-limit input instead of the former narrowing
  workaround.

The Rust-owned `MeteringConfig` URI parser and its test were deleted. Go
`TestMetering` delegates URI parsing to the separately versioned
`meter_config.NewFromURI` SDK; root `pkg/config` owns only the URI field,
defaults, loading, and validation context. Reimplementing that SDK parser in
this package was extra behavior, not Go parity. The stale ignored
`HostedEmbedding` gap was also deleted because that section does not exist at
the pinned commit.
