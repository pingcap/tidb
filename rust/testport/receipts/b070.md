## Structural facts that shaped the ports

- The rewritten/chunk tier keeps ONE evaluator per expression shape, so Go's
  vec-vs-scalar harness invariant becomes CROSS-TIER AGREEMENT over the exact
  generator arrays Go names; error rows are agreed-on errors, never dropped.
- Go's regexp caches (`regexpHandler`/`memorizedRegexp`,
  `constStrlistLookupCache`) are performance state keyed on statement context;
  this evaluator compiles per evaluation, so only their VALUE consequences are
  pinnable.
- `GETVAR`'s typed signature choice is Go's `BuildGetVarFunction` class switch
  on the declared type's eval type (`builtin_other.go:1207`); the port models
  that seam as `getvar_<int|uint|real|decimal|string>` names built by hand,
  which the session layer would mint.
- VALUES() and GETPARAM() evaluation read session slots (`CurrInsertValues`,
  `PlanCacheParams`) that have no evaluation path here; both are recorded as
  explicit gaps instead of approximations.

## Typed GETVAR follow-up

Go's `BuildGetVarFunction` selects `builtinGetTimeVarSig` when a session user
variable is declared as a MySQL time. Rust previously treated every
`Datum::Time` user variable as a string, so the `{"h"}` row from
`TestGetVar` was an explicit gap. The session binder now recognizes the time
domain, `builtin_return_type` exposes a DATETIME `getvar_time` node, and the
evaluator preserves the stored `Datum::Time` (or returns NULL for an unset
name). `getvar_time_variable_signature` is the focused regression.

## GETPARAM follow-up

Go's `getParamFunctionClass` declares an ETInt selector and the
`builtinGetParamStringSig` result is an ETString with
`mysql.MaxFieldVarCharLength` (65535) display width. The Rust `Columns` seam
now exposes the plan-cache lookup, and both the scalar/chunk and AST/value
paths return the selected datum's SQL string. Missing indices return the
same `Param index exceed param counts` sentinel; a NULL selector returns NULL.

## Not verified locally

- No RealTiKV/integration surfaces were exercised (change scope is
  unit-test-only inside tidb-expr; none required by the validation matrix).
- Legacy-`utf8_general_ci`-on-utf8-datum datum shapes (Go TestInFunc's exact
  collation spelling) cannot attach to utf8mb4-typed literals in this stack;
  the accent-fold equality is pinned through the shared general_ci weight
  table via the utf8mb4 name instead. The withdrawn first draft that used the
  legacy spelling is documented at the test.
- Byte-identical warning/error MESSAGE formats vs MySQL codes (e.g. Go's
  `[expression:1115]Unknown character set: 'cp866'`) are asserted here only up
  to the failure CLASS ("unknown character set"); Go's formatted text lives
  behind its terror stack, which this seed does not model.
