`pkg/expression/` on `origin/master`, sorted by (file path, line number),
chunked by cap 60. The slice spans:

and each carried behavior was re-derived from the production source it

`builtin_cast.go` helpers), not from existing Rust comments.

## Gaps (go-parity-gap ledger)

- go-parity-gap: FORMAT's PRECISION-side string coercion bypasses
  Columns::handle_truncate, so multi-source 1292 warning counts cannot be pinned.
- go-parity-gap: DATE()'s IgnoreZeroInDate/NoZeroDate SQL-mode arms need flag
  plumbing that the value-tier carrier does not expose.
- go-parity-gap: TO_BASE64's session-charset (GBK) constant conversion is not
  modeled; introducer syntax cannot reproduce converted constants.
- go-parity-gap: WEIGHT_STRING AS BINARY(n) cut does not emit the 1292
  "Truncated incorrect BINARY(n)" warning.
- go-parity-gap: builtinFuncCache[T] (lazy memo keyed by stmt ctx id) has no
  Rust counterpart — concurrency + lifecycle tests both affected.
- go-parity-gap: ADDTIME/SUBTIME typed DATE/DATETIME x STRING/DURATION arms
  lose right-operand fractional digits (left FSP wins) and accept unparseable
  strings instead of answering SQL NULL (issue #56861 matrices).
- go-parity-gap: ADDTIME DURATION-operand doors ignore a string second operand
  (03:00:00.999998 vs master 03:00:01.999997); wide-int date arm refuses
  int-as-datetime coercion.
- Master-table contradiction (documented, not approximated): TestBin expects
  NULL for `''` while `builtinCastStringAsIntSig`/oracle give 0 — kept visible
  in the bin carrier rather than fabricated.
