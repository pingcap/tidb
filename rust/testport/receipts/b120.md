## Adaptations and gap rationale

- The executable aggregate ports use real SQL over registered in-memory tables,
  feeding the same aggregate families as the Go direct `AggFunc` tests. SQL
  SUM over integer/unsigned inputs is asserted in the engine's DECIMAL result
  domain, matching MySQL behavior.
- `TestPercentile`'s FLOAT arm is retained as an ignored measured gap because
  the current Rust FLOAT storage-cell path returned a denormal bit-payload
  value; the running port covers the shared real accumulator through DOUBLE.
  The duration percentile fixture uses SQL TIME microsecond resolution while
  preserving the ordinal selection contract.
- Memory tests are recorded as gaps rather than guessed byte counts: Go pins
  `unsafe.Sizeof` partial-result structs and generated per-row memory deltas,
  while this tier exposes statement-level accounting instead.
- Merge and sliding tests are recorded as gaps where Go drives private
  `MergePartialResult`/`SlidingWindowAggFunc.Slide` seams in controlled order;
  the Rust equivalents are private to the parallel/recomputed execution
  pipeline.
- All spill entries are explicit white-box gaps. Go uses
  `SerializeHelper`/`DeserializeHelper` methods on concrete partial-result
  structs; Rust's `hash_agg/parallel.rs::write_partial` and `read_partial` are
  private and use a different aggregate-state wire format. Executor-level
  spilled-result behavior is covered by existing `hash_agg_spill_tests`.
