# Survive a dead cached TiKV leader in the checked Rust read path

This ExecPlan is a living document. Keep `Progress`, `Surprises & Discoveries`,
`Decision Log`, and `Outcomes & Retrospective` current as work proceeds.

Reference: `PLANS.md` at repository root. This plan is self-contained and must
be maintained according to it.

## Purpose / Big Picture

Campaign 12 transits pinned client-go's synchronous unary send-failure control
flow into the already connected Rust PD -> RegionCache -> TiKV coprocessor read
path. The same lazy response must survive loss of the cached TiKV leader after
the response has bound its ranges. It must classify the failed RPC, preserve
the observed address and channel generation, check foreground liveness, mutate
one shared store authority, probe another peer without changing leader-read
request flags, and complete the same logical task without advancing paging,
cache, EMA, or later-task state on the failed attempt.

The observable exit is a three-PD/three-TiKV TiUP proof. Rust binds a response
while its cache names leader A, the runner stops A, PD elects B, and only then
the same Rust process pulls the already-bound response. Success requires the
trace A -> alternate/B, exact failed-generation handling, no dispatch of a
future cached region through an epoch-stale store, an ordered structured TiKV
response, and strict cleanup. The runner may coordinate process phases but may
not supply region, peer, store, leader, address, or epoch metadata.

This campaign does not claim follower/stale/learner reads, forwarding, active
in-flight cancellation, configurable short-read fast rotation, background
store recovery, TLS health, batch/stream/TiFlash, locks, writes, slow score, or
production concurrency.

## Surprises & Discoveries

- Observation: Campaign 11 deliberately prohibited leader-mode fallback to an
  arbitrary follower, but pinned client-go does probe alternate peers while
  preserving `replica-read:false` and `stale-read:false`.
  Evidence: `ReplicaSelectLeaderStrategy` falls through to mixed candidate
  selection when the leader is unavailable; the alternate peer either returns
  `NotLeader` or succeeds if it has become leader.
- Observation: a failed Rust direct-unary send currently closes the whole
  response before any cache, channel, store, selector, backoff, or PD behavior.
  Evidence: `dispatch_attempt` maps `DirectUnaryClientError` directly to the
  terminal transport error and `fail` clears all future dispatch state.
- Observation: `RegionCache` has no shared Store authority. Every
  `RegionLocation` owns copied Store values, so one dead store cannot stale
  another cached region which references the same store generation.
- Observation: the tonic pool already increments address generations and
  ignores stale generation closes, but the generic client trait hides that API
  and tonic status mapping discards the gRPC code.
- Observation: testify suite methods are visible only as invalid method
  declarations. Only their top-level `suite.Run` root is actionable, so exact
  original test methods cannot be independently queued or evidenced.

  keep each region/attempt store epoch immutable.
  Rationale: an exact observed CAS increment automatically stales every region

  Date/Author: 2026-07-18 / Codex.

## Context and Orientation

`tidb-txnkv::RegionCache` owns region snapshots and recovery mutation.
`RegionLocation` currently embeds peers plus copied stores.
`ReplicaSelector` currently performs one stateless leader validation.
`TonicCoprocessorClient` owns an address-keyed generation pool but collapses
tonic codes into connection strings. `DirectUnaryQueryResponse` owns lazy task
order and region-error retry, yet treats every client error as terminal.

Pinned client-go's `sendReqState.next` selects a request context immediately
before each send. On send failure, caller cancellation and shutdown are
terminal. Remote gRPC Canceled closes only the failed address generation.
Other connection/timeout errors run foreground liveness; non-reachable state
CAS-increments the shared store epoch and marks it for re-resolution. The loop
backs off `BoTiKVRPC`, reselects a peer, rebuilds context, and resends. A leader
request retains leader flags while probing alternate peers. Exact candidates
are limited to 10 attempts or 50 seconds. Exhaustion invalidates/reloads the
region rather than returning terminal Client solely for a leaf RPC failure.

## Plan of Work

The store/selector slice introduces one store registry keyed by store ID inside
RegionCache. Loader-provided epoch zero never overwrites a newer canonical
epoch. Cached region peers capture the canonical epoch. An exact observed send
failure can update liveness and CAS-increment only the matching store epoch;
stale observations fail closed. It replaces the old stateless selector with a
request-scoped leader-first, alternate-voter state machine and deletes the
superseded authority after integration.

The tonic slice preserves a transport-neutral failure class including remote
gRPC code, address, and generation. It promotes exact generation-close to the
client trait, retains force-close for StoreNotMatch, and implements foreground
`grpc.health.v1.Health/Check` with reachable/unreachable/unknown results. Only
remote Canceled automatically requests exact generation close; ordinary
timeout and connection failures remain open for caller policy.

The DistSQL slice moves peer/context binding to dispatch time. One immutable
attempt holds region, peer, store, address, store epoch, and connection
generation. Send errors are consumed exactly once. Caller cancellation is
terminal without mutation. Remote Canceled generation-closes before retry.
Generic failures check liveness, conditionally invalidate the shared store
generation, reserve `TikvRpc` on the existing per-region budget, reselect, and
resend the same unconsumed task. Successful alternate-peer responses update the
leader. No failure advances result paging, cop cache, EMA, or later task order.

The root workspace repairs the external-test AST ledger. A suite method becomes
an obligation only when its receiver is passed to `suite.Run` by a valid
top-level Test and the method name/signature matches testify's zero-argument
`Test*` contract. The generated row kind distinguishes it from a standalone Go
runner and retains its exact path/line/name evidence anchor.

## Validation and Acceptance

Store tests prove one failure epoch stales every cached region referencing the
same store, a delayed failure cannot invalidate a newer generation, loader
epoch zero cannot roll back canonical state, address changes require
re-resolution, and no copied mutable store authority remains.

Selector tests prove leader-first routing; alternate voter probing with leader
request flags unchanged; max 10 attempts and 50-second limits; exclusion of
witness/learner/unreachable/stale-generation peers; deterministic exhaustion;
known/missing NotLeader integration; and successful alternate leader promotion.

Transport tests prove distinct local/caller cancellation, remote Canceled,
deadline, unavailable, invalid request/address, closed, and runtime families;
exact observed generation close; stale-close safety; no implicit close on
ordinary timeout; and foreground health mapping for serving, unknown, caller
cancellation, non-serving, and connection failure.

DistSQL tests prove the same logical task is resent; a failed attempt mutates no
success state; the exact generation is closed before remote-Canceled resend;
ordinary failures share the existing per-region budget; store invalidation
prevents a later already-bound region dispatching to a stale store generation;
paging and later-task order are preserved; cancellation has no mutation/sleep/
redispatch; and exhaustion rebuilds rather than returning terminal Client.

The live proof passes only if one retained Rust process performs:

    PD -> cached region leader A -> failed A#generation
       -> foreground health/store epoch transition -> alternate peer/B
       -> leader promotion -> structured ordered response

The marker must include failed address/generation, survivor address, zero stale
future dispatches, and recovered-store observation. Same-address reconnect alone
does not satisfy acceptance.

## Interfaces and Dependencies

`tidb-txnkv` owns topology, canonical store state, request selection, transport
facts, and exact cache mutation. `tidb-distsql` owns logical task ordering,
retry control, sleeping/cancellation, and successful result state. The transport
leaf must not import DistSQL or decide retry policy. DistSQL must not retain a
second mutable route/store map; immutable attempt observations exist only to
reject stale failures and responses.
