# Connect canonical cache maintenance and asynchronous request foundations

This ExecPlan is a living document maintained under repository-root
`PLANS.md`.

## Purpose / Big Picture

Campaign 16 consumes the honest Campaign 15 boundaries instead of adding
adapters around them. It admits 16 exact pinned production sources and 54 exact
original obligations as three non-overlapping implementation slices. One
slice owns the canonical RegionCache/store/PD/channel maintenance closure; one
owns BatchCommands opaque wire and in-flight ID state; one owns async
RegionRequest policy over the frozen one-attempt dispatcher.

The observable result is one cache and one transport authority that can later
be connected to a tonic duplex stream and live-cluster proof. No slice may
substitute unary futures for BatchCommands, replace the canonical store object,
create a second retry loop, or promote local injected events as live parity.

## Surprises & Discoveries

- `internal/kvrpc/batch.go` partitions mutation batches; it is not the
  BatchCommands transport and is deliberately excluded.
- Rust can retain opaque command bodies as length-delimited bytes at exact
  protobuf oneof field numbers, avoiding a reverse dependency on every TiKV
  request type while remaining wire-identical.
- Cache re-resolution, background health, delayed reload, and GC share one
  store/cache mutation authority. Separate loops or maps would make stale
  observations an architectural race rather than eliminate it.
- Async RegionRequest already has the necessary one-attempt dispatcher seam;
  it can be implemented independently of the eventual tonic stream.
- Cross-review found that Campaign 15's scheduler erased its completion behind
  a failure-only trait while the in-flight table needed the same concrete
  success completion. Campaign 16 expands the batch write set to the scheduler
  and consumes that authority directly instead of allocating a second once
  gate at transport publication.
- The first shared gate exposed a brittle source-text assertion for region
  errors after the async design changed. It was replaced with a behavior test
  proving one policy invocation, retry-state transfer, and zero publication.
- Evidence review found three manifest paths that named planned files which
  never existed. They were corrected to the real retained owners before a new
  frozen gate receipt was allowed to release claims.
- The maintenance driver and peer-vector observation guard are source-shaped
  but are not yet connected to the production read runtime. Likewise the async
  attempt has no concrete RegionCache/RequestSelector policy adapter and the
  batch authority has no tonic duplex stream. These are explicit `PARTIAL`
  boundaries, not hidden follow-up details.

  Rationale: they share exact cache, store, PD-loader, and channel write paths.

  Rationale: pending IDs, cancellation, demux, and route failure form one

  Date/Author: 2026-07-19 / root.

  integrated and source-reviewed.
  Rationale: shared builds are expensive; source/static checks provide the

## Plan of Work

Create checked slice claims before edits. Agents work only in their manifest
write sets and use `rustfmt` plus `git diff --check`; they do not build. Root
reviews source shape, integrates complete leaf commits, lands shared module and
Cargo seams once, runs exact pinned Go tests with 12 workers, then performs one
shared Rust gate.

The cache-maintenance slice must preserve identity, observation generation,
strict TTL, bounded GC, leader-only retry, direct-versus-publishing lookup, and
shutdown. The batch slice must preserve exact tags, pending-before-send,
cardinality validation, cancellation retirement, max response ID, and
forwarded-route isolation. The async slice must reuse the same selector and
retry/cancellation authority as synchronous requests.

## Validation and Acceptance

Every manifest test anchor must run in its pinned Go module with `go test -p
12`. Rust leaf tests remain source-shaped and injected until the combined gate;
the final command is:

    cd rust
    CARGO_BUILD_JOBS=12 scripts/rewrite-gate.sh integrate

`make -j12 lint` is required for Ready. A later campaign must connect tonic
duplex streams and run a real PD/TiKV proof before BatchCommands or background
recovery can be called live-complete.
