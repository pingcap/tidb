# Put a real TiKV socket below the checked read path

This ExecPlan is a living document. Keep `Progress`, `Surprises & Discoveries`,
`Decision Log`, and `Outcomes & Retrospective` current as work proceeds.

## Purpose / Big Picture

Campaign 09 replaces the last fake boundary below Campaign 08 with real
network behavior. One parallel slice ports client-go's address-keyed unary
connection lifecycle and the exact `tikvpb.Tikv/Coprocessor` gRPC call. The
other ports the single-region leader/cache/request-sender authority that must
eventually choose that address and attach region context exactly once.

The campaign exit is a real TiKV unary request through the existing checked
request/response/read-owner chain, plus source-backed region routing that is
ready for a concrete PD loader. It is not yet a deployable TiDB server:
concrete PD discovery is owned by a separately pinned Go module, and the
current COM_QUERY path still uses the in-memory catalog/executor.

## Surprises & Discoveries

- Observation: client-go's RegionCache does not own concrete PD transport.
  Evidence: it consumes `github.com/tikv/pd/client`, pinned at
  `v0.0.0-20260708075407-4e05b9d2c2d3`. Campaign 09 keeps an injected loader
  and will not label that boundary production PD.
- Observation: the current Rust coprocessor request can carry region context
  both beside and inside encoded request bytes.
  Evidence: client-go attaches `req.Context` only after route selection through
  `tikvrpc.AttachContext`. The real Rust sender must establish the same single
  authority before serialization.
- Observation: external runnable-test inventory records top-level suite
  declarations but not nested `t.Run` cases.
  Evidence: RegionCache, request-sender, and replica-selector suites contain
  focused nested cases not independently visible in the current runner ledger.
  Their exact anchors remain mandatory support evidence until the external
  inventory is extended.

## Decision Log

- Decision: use tonic only as the lowest RPC leaf.
  Rationale: the source-shaped architecture remains DistSQL task/paging →
  RegionRequestSender → RegionCache/PD loader → CoprocessorRpc → channel pool.
  Tonic must not leak into planner, executor, server, or DistSQL ownership.
  Date/Author: 2026-07-18 / Codex.
- Decision: keep the existing synchronous SendRequest-shaped capability for
  this campaign.
  Rationale: it matches client-go's public call boundary and avoids forcing an
  async rewrite upward before cancellation/parallel dispatch are source-owned.
  The RPC leaf owns its runtime and channel lifecycle internally.
  Date/Author: 2026-07-18 / Codex.
- Decision: a static-route live request is transport proof, not RegionCache or
  production-read completion.
  Rationale: acceptance and status must preserve that distinction so Campaign
  10 can add governed PD discovery without deleting a fake topology API.
  Date/Author: 2026-07-18 / Codex.

## Plan of Work

The setup commit adds empty `txnkv::rpc` and `txnkv::region` authorities and
all shared routing declarations. The RPC worktree owns Cargo/protobuf changes,
the address-keyed channel pool, typed errors, unary client, focused tests, and
the live probe. The region worktree owns only new region files, focused tests,
and its external evidence. Neither edits generated ledgers, campaign records,
or the other's Rust paths.

After both commits return, the steward verifies that context is attached once
after route selection, that close/reopen and timeout/error identity remain
source-shaped, and that no PD/static-route claim leaks upward. The steward then
regenerates external and TiDB ledgers and runs one full integration gate.

## Validation and Acceptance

Focused RPC tests must cover lazy address pool creation, round-robin/reuse,
CloseAddr recreation, Close terminal behavior, caller timeout, raw response
bytes, and address/version error identity. A real TiKV probe must cross the
generated `/tikvpb.Tikv/Coprocessor` method; a structured TiKV response proves
transport only unless the test also supplies source-derived table/range/DAG
metadata and verifies rows.

Focused region tests must cover key containment, cached hit/miss, injected
loader fill, leader/store/address selection, cache invalidation, cluster ID,
and exactly-once context attachment. Unsupported replica modes, missing leader
or store address, stale epoch, and multi-region input fail closed.

Final validation is:

    CARGO_BUILD_JOBS=12 rust/scripts/rewrite-gate.sh integrate
    make -j12 lint

If a TiUP playground is started, use the cleanup-safe RealTiKV lifecycle and
prove the exact PD endpoint is unreachable after teardown.
