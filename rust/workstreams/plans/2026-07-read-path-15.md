## Purpose / Big Picture

Campaign 15 directly transits the two dependency chains that Campaign 14 made
visible but could not honestly implement: PD bucket wire before RegionCache
bucket/batch behavior, and completion/scheduling before BatchCommands async
requests. The campaign is admitted as 11 exact production sources and 53 exact
original obligations, with pairwise-disjoint Rust write sets and one delayed
12-job integration gate.

The observable result is not a Rust-only approximation. A pinned PD response
can carry exact bucket metadata and ordered batch-scan regions into the sole
RegionCache authority; the cache applies Go's strict TTL, half-open traversal,
bucket version/clamp, gap, and range-limit rules. In parallel, a source-shaped
one-shot completion driver and BatchCommands scheduler preserve cancellation,
priority, grouping, observations, and adaptive policy without pretending a
tonic unary future is client-go `SendRequestAsync`.

## Surprises & Discoveries

- Observation: Rust already asks PD for buckets but its bounded protobuf omits
  `GetRegionResponse.buckets`; cache-only bucket fixtures would therefore prove
  a path production can never receive.
- Observation: `SendRequestAsync` hard-requires the BatchCommands client. It is
  not asynchronous execution of the ordinary unary RPC.
- Observation: full BatchCommands transport and RegionRequest async policy
  overlap at one queue/callback/close authority. The dependency-closed parallel
  work is completion plus scheduler first, then the wire stream and callback.
- Observation: TiFlash recovery shares the canonical RegionCache TTL, labels,
  bucket metadata, and endpoint validation. It is a second rotation of the
  cache authority, not a disjoint first-wave leaf.
- Observation: background GC and coalesced bucket refresh require owned cache
  snapshots and one shared lock. Attaching threads to the current borrowed,
  `&mut self` cache would create a second authority.

## Context and Orientation

`rust/crates/tidb-pd-client/src/client.rs` owns one dedicated PD runtime worker
and endpoint-keyed client map. `tidb-txnkv/src/pd_loader.rs` is the only adapter
from PD models to `RegionLocation`. `tidb-txnkv/src/region/cache.rs` is the sole
ordered region/store authority. `tidb-txnkv/src/rpc/unary.rs` owns the existing
TiKV runtime and channel pool; Campaign 15 must not add another runtime.

The exact pinned control-plane fields are `metapb.Buckets` fields 1-5,
`GetRegionResponse.buckets = 7`, `pdpb.Region.buckets = 5`, and ordered
`BatchScanRegionsRequest` ranges. Expiry is strict `now > ttl`; bucket updates
are monotonic; a stale/no-bucket region replacement retains newer cached
buckets; cached traversal stops at expiry, reload, a hole, end, or limit.

## Plan of Work

Root lands only module declarations and narrow contracts. Four feature agents
then work in per-slice branches and worktrees. The wire leaf changes only proto,
PD client/model, loader, and their existing source tests. The cache leaf owns
location/cache plus new TTL/bucket/batch modules and tests. The completion leaf
owns the async contract/driver and its tests. The scheduler leaf owns only the
new batch submodules and tests. Shared Cargo manifests, generated ledgers,
evidence transfers, release status, and final docs remain root-owned.

Agents use exact Go source/tests, `rustfmt --check`, source selectors, TSV checks,
and `git diff --check`. They do not run Cargo workspace builds. Root integrates
all substantial leaves before the first Rust build, then runs exact original Go
tests and one shared Rust/Ready gate.

## Validation and Acceptance

Wire tests prove every pinned field number, bucket preservation/clearing, scan
ordering, range limits, and response metadata. Cache tests prove strict TTL,
half-open containment, overlap replacement, 128-region batch size, 2048-range
cap, bucket monotonicity/clamping, fallback only on Unimplemented, holes, and
positive-infinity bounds. Completion tests prove reverse injection and exactly
one terminal result across every invoke/schedule race. Scheduler tests prove
priority stability, backing-array reference clearing, cancellation, terminal
observations, grouping, concurrency limits, and every batch-policy table row.

No slice is promoted from an original Go obligation merely because a Rust unit
test has a similar name. The evidence artifact must identify the exact source
rule and all nested subtests. A later live proof must use real PD/TiKV sockets;
this foundation campaign does not call injected buckets or a unary request a
live BatchCommands proof.

## Idempotence and Recovery

Claims precede worktrees. Feature branches are merged without force. A failed
static check is fixed on the owning leaf before integration. No workspace build
receipt exists until every leaf and evidence transfer is frozen. Any post-gate
implementation, test, script, manifest, or undeclared Rust edit invalidates the
receipt and requires a fresh gate.

## Interfaces and Dependencies

`BucketMetadata` is transport-neutral and immutable. PD owns decoding; cache
owns retention and publication. `AsyncRequestDispatcher::begin` starts exactly
one request and returns a `PendingRequest`; it neither looks up topology nor
mutates feedback. The completion driver owns ready state and once-only terminal
delivery without a second Tokio runtime. Batch scheduler owns ordering and
grouping, not sockets. RegionCache remains the only mutable topology authority.
