## Purpose / Big Picture

Campaign 14 directly transits the next connected pinned client-go read-routing
ring after Campaign 13. A real Rust read will retain one logical TiKV target,
optionally connect through one healthy proxy, emit the exact forwarding
metadata, prefer stores by labels and health, divert a read around reported
load, and feed success or failure back into the sole RegionCache authority.

The observable outcome is one three-TiKV proof in which the Rust client first
selects by source-shaped score, diverts around a busy store, forwards to a
leader through a follower when direct liveness fails, reuses or rotates the
proxy, and returns to the direct leader after recovery without duplicating
topology, channel, retry, deadline, or publication state.

## Surprises & Discoveries

- Observation: the source family is ten files, not eight. `region_request.go`
  directly constructs the network metrics collector, and `pd_codec.go` remains
  a RegionCache topology neighbor.
- Observation: forwarding is not a request-policy boolean in pinned client-go.
  RegionCache owns enablement and preferred proxy identity; each immutable
  dispatch owns both a logical target and optional physical proxy.
- Observation: the exact score is ordered by bit significance:
  NotSlow, LabelMatches, PreferLeader, NormalPeer, NotAttempted. Label mismatch
  is a preference and falls back to leader rather than failing.
- Observation: a positive ServerIsBusy estimate updates a decaying load value;
  a zero estimate marks the client-side slow score immediately. No-idle
  fallback clears the busy threshold and retains the region.
- Observation: the current bounded PD projection drops `metapb.Store.labels`.
  Topology must carry those labels through `PdStore` and `PdRegionLoader`; an
  injected cache-only label test would not prove the live path.
- Observation: the pinned kvproto field is `metapb.Store.labels = 4`; field 8
  is `git_hash`. Copying a newer remembered schema instead of the pinned wire
  declaration would silently corrupt store metadata.
- Observation: the focused Campaign 14 tests were green, but the broader
  package regression found two structural assertions that still searched for
  the old direct-only `send_request_with_context` call. Updating them to assert
  the new route-aware call caught source-shape drift without changing runtime
  behavior.
- Observation: the first all-target integration attempt found the preexisting
  sparse PD wire fixture constructing `metapb.Store` without the new exact
  `labels` field. The repaired fixture now asserts both labels field 4 and
  node-state field 13 before the gate is retried from a fresh snapshot.
- Observation: the next strict-Clippy attempt rejected a manual nonzero check
  around slow-score interval division. `checked_div` expresses the real
  optional-average state directly and preserves the zero-update tick without
  a special-case arithmetic branch.
- Observation: a faithful live forwarding proof does not require killing the
  logical leader. Recording the foreground direct-unreachable fact while the
  leader remains available lets a real TiKV proxy forward to it; stopping the
  target would test an impossible proxy route rather than client-go behavior.

## Decision Log

- Decision: extend the existing `LeaderRequest` route decision with `target`
  and optional `proxy` attempts instead of adding a second `RouteDecision`
  wrapper.
  Rationale: direct and forwarded requests then share one immutable route; only
  dispatch address, forwarded host, and feedback subject differ.
  Date/Author: 2026-07-19 / root.
- Decision: keep mutable labels, health, load, generation, and preferred proxy
  inside RegionCache-owned StoreState.
  Rationale: selector and transport must not become second topology stores.
  Date/Author: 2026-07-19 / root.
- Decision: use deterministic injected time/seed in source tests while retaining
  Go's ordering semantics.
  Rationale: sleeps and global randomness obscure edge-case precedence without
  adding product behavior.
  Date/Author: 2026-07-19 / root.
- Decision: defer async/batch/stream forwarding and background feedback loops,
  but keep their exact original declarations registered as explicit gaps.
  Rationale: this campaign closes the production synchronous unary path without
  inventing absent async or batch authorities.
  Date/Author: 2026-07-19 / root.
- Decision: embed one `StoreRoutingHealth` in the canonical RegionCache
  `StoreState` and preserve it across PD metadata refresh.
  Rationale: labels, generations, slow/load health, and preferred proxy then
  remain one store authority instead of becoming selector- or transport-local
  shadow state.
  Date/Author: 2026-07-19 / root.
- Decision: make the live gate enter through the retained DistSQL transport,
  inject only the observed direct-liveness fact, and require real Cop responses
  for first proxy, proxy reuse, and recovered direct dispatch.
  Rationale: target/proxy/header/publication behavior is exercised on real
  TiKV sockets while topology, channel, and response ownership stay production
  code rather than shell-fabricated substitutes.
  Date/Author: 2026-07-19 / root.

## Context and Orientation

`rust/crates/tidb-txnkv/src/region/cache.rs` is the sole topology and store
authority. `request_selector.rs` owns request-local attempt history.
`rust/crates/tidb-distsql/src/cop_paging/direct_unary_query_transport.rs` owns
retry/publication order. `rust/crates/tidb-txnkv/src/rpc/unary.rs` owns the sole
channel pool and raw tonic request.

A target is the TiKV peer that must interpret the region request. A proxy is a
different TiKV connection which forwards that request to the target. A
`LeaderRequest` is immutable and carries both identities. `RouteFeedback` says
which physical route succeeded or failed; RegionCache alone applies it.

## Plan of Work

seam, creates owner-specific evidence and checked transfers, runs pinned Go

region-cache TTL/batch traversal, async replica requests, and TiFlash

## Validation and Acceptance

Topology tests prove immutable snapshots, exact target/proxy generations,
preferred-proxy publication/clearing, stale-feedback rejection, and unchanged
ordered lookup. Health tests prove every declared Go case row, score bit,
strict busy comparison, 500/800/150 ms decay scenario, 30-second immediate
slow mark, threshold 80, and no-idle leader fallback. Forwarding tests prove
empty metadata omission, exactly one nonempty metadata value, physical proxy
failure, proxy rotation/reuse, cancellation precedence, and direct recovery.

The live proof must emit target and proxy stores, dispatch address, forwarded
host, score/load facts, usable Cop response, proxy reuse or rotation, direct
recovery, and cleanup markers. A successful RPC alone is insufficient.

## Interfaces and Dependencies

`LeaderRequest` must expose a logical target, optional proxy, dispatch address,
and optional forwarded host without mutable cache access. `RouteFeedback` must
identify the exact target/proxy generation and success/failure class. The
health/scoring leaf consumes immutable store facts and returns a pure ranking;
the forwarding leaf consumes only the route decision. RegionCache remains the
only component allowed to publish proxy preference or mutate store state.
