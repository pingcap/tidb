# Close replica policy, active cancellation, and optimistic read locks

This ExecPlan is a living document. Keep `Progress`, `Surprises & Discoveries`,
`Decision Log`, and `Outcomes & Retrospective` current while implementing it.

Reference: `PLANS.md` at repository root. This plan is self-contained and must
be maintained according to it.

## Purpose / Big Picture

Campaign 13 directly transits the next three pinned-Go read-path gaps after
Campaign 12: nonleader replica policy, cancellation of an already-dispatched
unary RPC, and bounded optimistic lock recovery. The purpose is not three more
helpers. One retained Rust read path must be able to choose a requested voter,
interrupt a hanging call without recovery mutation, and consume a TiKV locked
response by checking/resolving the lock through the same client/cache before
retrying only the unconsumed task.

The structural prerequisite is one root seam extraction. The current tonic
Coprocessor worker becomes a command-neutral raw unary core which remains the
sole owner of ChannelPool generations and deadlines. One `SharedReadRuntime`
owns the client and RegionCache handles. The direct-unary loop delegates
cancellation and locked-response decisions into isolated leaves. After that
commit, the three behavior slices have disjoint Rust write sets and cannot
invent second transport, topology, or retry authorities.

The campaign explicitly defers forwarding/proxy metadata, label/load/slow-score
policy, busy thresholds, production async APIs, background store or lock
recovery, TLS, batch/stream/TiFlash, pessimistic and async-commit locks,
TxnNotFound retry, writes/2PC/1PC, production concurrency/TTL, general DAG/table
lowering, and COM_QUERY integration.

## Surprises & Discoveries

- Observation: the remaining behaviors are semantically independent but all
  initially appeared to require edits to the same tonic worker and direct
  response loop. The collision is structural, not inherent to Go behavior.
- Observation: pinned client-go has no direct synchronous optimistic resolver
  unit test. Its two resolver tests are async/cache-specific. They remain
  visible partial obligations; source-shaped branch tests plus a real TiKV
  committed-primary/locked-secondary proof are required for the bounded slice.
- Observation: testify suite expansion added in Campaign 12 makes the replica
  and cancellation method obligations independently claimable by exact parent.
- Observation: the first replica commit proved selector scoring and a live
  address-directed Cop RPC, but an independent audit found that production
  DistSQL still constructed `ReadPolicy::default()`. The direct proof is not an
  end-to-end runtime proof until request metadata drives that selector.
- Observation: `DataIsNotReady` and known-leader `NotLeader` are selector state
  transitions in pinned client-go, not generic terminal region errors. Keeping
  them in the generic recovery result loses required fallback behavior.
- Observation: pinned client-go records route success immediately after ruling
  out a region error, before TiDB interprets `Response.Locked`. A locked reply
  therefore may update leader routing, but must not update paging, read-byte
  EMA, publication, or task-consumption state.
- Observation: independent final audits found three false completion paths:
  cancellation was optional transport configuration rather than request
  ownership, replica seeds were allocated at first task dispatch rather than
  query binding, and the initial lock live test duplicated an uninstalled
  production delegate. Acceptance now requires the real retained constructors
  and post-operation state, not a parallel proof harness.
- Observation: `CheckTxnStatusResponse.lock_ttl` is the transaction lock's
  absolute lifetime, not a fresh sleep duration. Remaining wait must be derived
  from the lock start TSO and the exact current TSO.
- Observation: current `pd/client` enables its router client during
  construction, before TiDB can apply the default-OFF SQL variable. PD v8.5.6
  therefore rejects bootstrap with an unimplemented `QueryRegion`; v8.5.7 is
  the first adjacent stable patch whose server contains that RPC. The live
  runner must pin a coherent v8.5.7 PD/TiKV playground.
- Observation: client-go commits the whole region batch containing the primary
  before spawning secondary commits. Two rows in one region therefore cannot
  create the required committed-primary/locked-secondary state even when the
  secondary failpoint fires. The source-shaped fixture must split at row 2,
  exactly as the pinned RealTiKV test separates the transaction's batches.

## Decision Log

- Decision: extract one generic unary core instead of adding a second tonic
  client for transactional commands.
  Rationale: address generation, channel lifetime, deadlines, and cancellation
  are transport facts and must have one authority.
- Decision: put CheckTxnStatus and ResolveLock above the generic core and keep
  lock retry in DistSQL.
  Rationale: transport must not own lock or retry policy.
- Decision: atomically succeed the Campaign 12 replica owner with the full
  file-granular seven-file locate family.
  Rationale: the external ledger cannot truthfully split Go files by symbol.
- Decision: keep forwarding, labels/load/slow-score, async-commit and
  pessimistic locks explicit rather than weakening their tests into the
  bounded runtime.
  Rationale: those paths require additional protocol or lifecycle authorities.
- Decision: reject the first live replica marker as production acceptance even
  though TiKV served the request.
  Rationale: the test bypassed `QueryTransport::send`; acceptance requires the
  real metadata-to-policy and selector-recovery path plus decoded query data.
- Decision: pass the exact Cop `UnaryCallContext` into lock recovery instead of
  copying only its timeout.
  Rationale: status, resolve, and TTL waiting must observe the same monotonic
  caller-cancellation authority; a replacement carrier would split ownership.
- Decision: replace optional active-cancellation and retry-cancellation seams
  with one mandatory execution-owned carrier on every `TransportRequest`.
  Rationale: pre-dispatch, in-flight RPC, post-RPC precedence, retry waiting,
  response close, and executor close must be one monotonic authority.
- Decision: make `UnaryCallContext` retain one absolute deadline.
  Rationale: restarting the full timeout for Cop, CheckTxnStatus, ResolveLock,
  and TTL wait violates the single source request budget.
- Decision: retain one execution-level cancellation parent but mint and
  register a local child for every bound transport request.
  Rationale: executor cancellation must fan out to every active request, while
  closing one response must cancel only that response and never its siblings.
- Decision: scope Campaign 13 cancellation to the bound unary read lifecycle,
  not initial PD discovery.
  Rationale: PD discovery currently precedes query binding and already owns a
  separate timeout; claiming one deadline across it without carrying the same
  cancellation authority into `RegionLoader` would be false completion.

## Context and Orientation

`tidb-txnkv::RegionCache` is the only topology/store/selector authority.
`TonicCoprocessorClient` currently owns one worker and ChannelPool. Campaign 13
extracts that worker without changing its ownership. `DirectUnaryQueryResponse`
is the only task/retry/success-mutation authority and will delegate two facts:
whether the caller cancelled an in-flight attempt and whether a decoded locked
response was resolved or must wait.

Pinned client-go constructs an access path from replica mode and ordered legal
peers, then advances that path under failure/fallback rules. Its RPCCanceller
registers an in-flight request context and cancellation is checked before
send-failure recovery. Its optimistic lock resolver decodes LockInfo, checks
the primary transaction status, returns a TTL for a live transaction, or sends
ResolveLock for committed/rolled-back secondary keys before the caller retries.

## Plan of Work

First land the root seam slice. Move worker/channel dispatch into
`rpc/unary.rs`, introduce the canonical cancellation carrier and typed
transaction command adapters, and keep `TonicCoprocessorClient` as the Cop
context/path adapter. Add `SharedReadRuntime` and predeclare the cancellation
and lock delegates in the DistSQL loop with fail-closed placeholder outcomes.
Run focused tests once because this is the substantial structural build point.

Then claim three worktrees from that commit. The replica slice edits only the
region selector/cache leaves and its tests. The cancellation slice edits only
the canonical cancellation and delegation leaves plus hanging-server tests.
The lock slice edits only new lock model/resolver/delegation leaves plus its
live proof. Agents read the complete owned Go files/tests and produce
owner-named evidence; root alone updates registries, generated inventories,
and predecessor transfers.

## Validation and Acceptance

The seam passes only if all existing Campaign 12 tests still pass, Cop requests
retain exact context bytes/generation/failure classes, new transactional
commands reuse the same channel generation, and placeholder delegates fail
before behavior or success mutation.

Replica tests prove follower/mixed/prefer-leader/stale/learner access paths,
deterministic seed rotation, legal peer admission, exact request flags,
fallback state, and unreachable/stale-store exclusion. The live proof must
discover topology from PD, select a real nonleader voter under follower policy,
send `replica_read=true`, receive a usable response, and never promote it as
leader. Learner remains deterministic-only unless the runner provisions one.

Cancellation tests prove a hanging in-flight tonic request returns caller
cancellation promptly and performs no channel close, liveness, cache/store,
selector, backoff, PD, paging, EMA, publication, or later-task mutation.
Timeout and remote Canceled retain their Campaign 12 behavior. This acceptance
starts at query binding; initial PD discovery keeps its separately bounded PD
timeout until a later campaign carries the same request authority into the
region loader.

Lock tests prove exact LockInfo/shared-lock mapping; optimistic/non-async
admission; committed, rolled-back, and alive status; lite-key ResolveLock;
alive TTL wait through the exact Cop cancellation context; same-task/range
retry; route-success observation before lock handling; and zero paging, EMA,
publication, or task-consumption mutation for the locked attempt. The live
marker must include start TS, locked key, primary route, committed
status/commit TS, resolve route and key, two Cop attempts, one published
response, and zero stale/duplicate publication.

## Idempotence and Recovery

Claims are taken before worktrees. Any ownership consolidation creates the
replacement evidence and transfer before removing predecessor artifacts.
Failed live runs retain logs and always remove owned TiUP tags/processes/data.
The shared gate receipt is valid only for its exact immutable claim/workspace
hash; any implementation/test/script/manifest change requires a new gate.
