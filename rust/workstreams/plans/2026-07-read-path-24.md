# Detach clustered signed-BIGINT ranges and share the live SQL harness

This ExecPlan is a living document and follows `PLANS.md`.

## Purpose / Big Picture

Campaign 24 removes Campaign 23's unconditional full-table range without creating a key-only query path. A source-shaped signed-BIGINT ranger separates clustered-primary-key access conditions from residual conditions. DistSQL converts the logical ranges into exact half-open TiDB record-key ranges. The existing TiKV Selection remains the semantic owner for residual predicates. A shared live harness replaces duplicated Campaign 22/23 orchestration so later vertical slices add scenarios instead of another 1,500-line runner.

## Decision Log

- Range pruning optimizes the Campaign 23 Selection path; it does not replace it.
- Planner owns logical boundaries and access/residual partitioning. DistSQL alone owns physical TiDB key bytes.
- Contradictions normalize to zero ranges and short-circuit before TSO or transport.
- `!=` remains two ordered ranges; MIN/MAX boundaries eliminate empty halves rather than emitting invalid ranges.
- The live harness owns lifecycle and safety, while scenario scripts own SQL expectations and plan evidence.
- Cleanup containment depends on current exact tag ownership and zero descendants, not on whether the happy path reached a detached-child milestone.
- Generic Go-compatible `DatumRange` encoding preserves source-shaped empty physical intervals; normalized planner `SignedHandleRange` validation remains separate, and both use one physical key encoder.
- Campaign closure rejects duplicate post-close evidence ownership during dry-run, before the expensive workspace gate.
