# Survive PD and region-leader movement in the checked Rust read path

This ExecPlan is a living document. Keep `Progress`, `Surprises & Discoveries`,

## Purpose / Big Picture

Campaign 11 turns Campaign 10's one-shot PD-backed read route into a bounded
production recovery loop. A caller still supplies only plaintext PD seed
addresses. Rust discovers the PD membership, survives loss of the selected PD
leader through a discovered member, interprets TiKV region errors in pinned
client-go handler order, mutates the sole `RegionCache` authority, rebuilds only
the failed task's remaining ranges, and completes the same lazy DistSQL query
after a region-leader change or ordinary stale topology.

The observable exit is one pinned TiUP test with three PD and three TiKV
processes. The same Rust process must retain its client and cache while the
runner removes the active PD leader and transfers the target region leader.
Success requires a structured TiKV response after both changes and proof that
Rust selected the PD and TiKV survivors from discovered topology. No shell,
Python, environment variable, or fixture may provide region, peer, store, or
TiKV-address metadata.

This campaign is deliberately not full client-go parity. It does not claim
background health loops, TLS, forwarding, follower/stale reads, lock
resolution, generic TiKV connection-failure retry, TiFlash/batch coprocessor,
or production concurrency.

## Surprises & Discoveries

- Observation: before Campaign 11, Campaign 10 preserved every outer `errorpb.Error` field number
  but intentionally erased the two nested payloads required for recovery.
  Evidence: `errorpb.NotLeader.leader` and
  `errorpb.EpochNotMatch.current_regions` are absent from the Rust projection,
  while pinned client-go uses both to choose immediate resend versus cache
  replacement.
- Observation: TiDB does not generically retry a failed RPC.
  Evidence: `RegionRequestSender.onRegionError` first applies a typed cache and
  route transition; `copIteratorWorker.handleCopResponse` then backs off,
  rebuilds the failed task's ranges, and prepends the one-or-more replacements.
- Observation: a region error can coexist with other outer error fields.
  Evidence: pinned client-go requires its exact `onRegionError` handler
  order. A Rust enum produced by checking fields in a different order would
  change behavior for a legal protobuf message.
- Observation: before Campaign 11, the PD client learned a cluster ID from `GetMembers` but
  discards every discovered member and permanently retains one channel.
  Evidence: loss of that endpoint makes every later `GetRegion` and `GetStore`
  fail even though the bootstrap response already named survivors.
- Observation: full lock handling is downstream of much more than a lock
  protobuf.
  Evidence: the Go resolver depends on Oracle/status RPCs, resolved/committed
  timestamp state, region regrouping, and detached async cleanup which
  intentionally does not inherit caller cancellation.
- Observation: active RPC cancellation cannot be claimed through the current
  synchronous `QueryResponse` and serial tonic worker.
  Evidence: `close` cannot interrupt a blocking `send_request`; Campaign 11 can
  make sleep and pre-retry mutation cancellation-aware, but in-flight RPC
  cancellation requires a later async transport/lifecycle increment.
- Observation: TiDB rebuilds only the failed cop task, not the already prepared
  logical tail.
  Evidence: `copIteratorWorker.handleCopResponse` passes only `task.ranges` to
  `buildCopTasks` and prepends those replacements; later tasks retain their
  identity, paging size, route, and prepared attempt until they fail themselves.
- Observation: `EpochNotMatch.current_regions` is an available sibling subset,
  not a promise of contiguous full coverage of the old region.
  Evidence: pinned client-go hydrates and inserts every returned region, then
  invalidates the old snapshot without rejecting gaps or partial coverage.
- Observation: a reachable old PD leader can return a transport or header
  error after election while the local member snapshot still names it leader.
  Evidence: foreground membership revalidation is required before deciding
  whether an application failure is terminal or should reach the refreshed
  leader.
- Observation: excluded ServerBusy sleep can run past 64 exponential attempts.
  Evidence: a shift-based exponential overflowed before the source 600-second
  exclusion cap; saturating multiplication preserves the configured cap.
- Observation: release validation found two claimed external test-suite roots
  that implementation evidence had exercised only partially but the generated
  ledger still called `UNTRIAGED`.
  Evidence: release rejected
  `TestReplicaReadAccessPathByBasicCase`,
  `TestReplicaReadAccessPathByLeaderCase`, and then
  `TestRegionRequestToThreeStores` until exact `PARTIAL` rows named both the
  executed leader/recovery cases and the still-external follower, forwarding,
  async, transport-rotation, and broader error-matrix branches.

## Decision Log

- Decision: transit the pinned Go control flow directly instead of wrapping
  Campaign 10's terminal region error in a counter-only retry loop.
  Rationale: known-leader, no-leader, epoch replacement, terminal, and retry
  errors have materially different cache and task behavior.
  Date/Author: 2026-07-18 / Codex.
- Decision: keep `RegionCache` as the only topology authority and place exact
  error-to-cache transitions in `tidb-txnkv`; DistSQL owns only failed-range
  ordering, resend/rebuild, and query lifecycle.
  Rationale: putting a second route map or epoch table in DistSQL would recreate
  the split authority deleted by Campaign 10.
  Date/Author: 2026-07-18 / Codex.
- Decision: splice one-to-many replacements at the failed logical task and
  leave every later task untouched.
  Rationale: rebuilding the entire undispatched tail would add PD work, change
  paging ownership, and diverge from the pinned Go control flow.
  Date/Author: 2026-07-18 / Codex.
- Decision: split implementation into three write-disjoint slices: PD member
  refresh, txnkv wire/cache recovery, and DistSQL retry orchestration.
  Rationale: their public boundary can be frozen before fan-out, while each
  agent owns a coherent source/test family and no shared Rust file.
  Date/Author: 2026-07-18 / Codex.
- Decision: include foreground PD member refresh and direct endpoint failover,
  but not background health checks or forwarding.
  Rationale: the bootstrap already returns the required member set, and trying
  each discovered direct endpoint once is a dependency-closed control-plane
  behavior. Health scheduling and forwarded-host semantics are separate owners.
  Date/Author: 2026-07-18 / Codex.
- Decision: keep one 20-second backoff budget per region ID and share that
  budget across client-like resend and TiDB outer rebuild, with an injected
  cancellation-aware sleeper.
  Rationale: separate budgets would permit more work than Go and a real sleep
  hidden in cache code would make cancellation and tests incorrect.
  Date/Author: 2026-07-18 / Codex.
- Decision: defer locks, active in-flight cancellation, TLS, forwarding,
  follower/stale reads, and generic TiKV connection-failure retry.
  Rationale: the required async cleanup, secure channel, replica selector, and
  connection-generation lifecycles do not exist. Config-only or
  synchronous-only substitutes would be false parity.
  Date/Author: 2026-07-18 / Codex.

## Context and Orientation

Before this campaign, Campaign 10's `PdClient` was a one-endpoint control-plane leaf.
`PdRegionLoader` converts PD regions and stores to immutable
`RegionLocation`s. `RegionCache` owns ordered versioned snapshots and exact
invalidation. `DirectUnaryQueryResponse` owns lazy sequential TiKV dispatch,
one `CopReadTaskRuntime`, logical response order, and the shared cache handle.
The read-task runtime owns successful cache/paging/EMA state; before Campaign
11 it rejected a region error without consuming the failed attempt.

The pinned Go recovery sequence has two levels. The client-like level examines
the exact region error and either resends to an updated leader, retries the
current route after typed backoff, invalidates/replaces cache topology and asks
the caller to rebuild, or returns a terminal error. The TiDB cop level consumes
the failed task's unconsumed ranges, locates them again, and prepends the
replacement tasks. A split can replace one task with several; successful pages
already returned to the caller must never be replayed.

The PD slice retains every normalized client URL from `GetMembers`, validates
one nonzero cluster identity across responses, refreshes the set from any known
member, and tries discovered direct endpoints deterministically for
`GetRegion` and `GetStore`. It must not add background threads, HTTPS, forwarded
metadata, generic unbounded retries, or router-service behavior.

The txnkv slice restores the exact nested protobuf payloads, translates region
errors in pinned client-go handler order, and owns atomic cache mutations. Known
`NotLeader` updates only the leader if that peer still belongs to the exact
region. Empty `NotLeader` invalidates and rebuilds after scheduling backoff.
`EpochNotMatch` with no regions invalidates; with an older TiKV epoch it retries
under budget; otherwise it resolves every peer store, atomically replaces all
returned current regions, and invalidates the old region unless an exact
replacement exists. Invalid, removed, stale, or delayed observations fail
closed. StoreNotMatch invalidates the exact observed route for a later reload.

The DistSQL slice consumes a failed attempt exactly once, never populates the
cop cache or advances paging/EMA on an error, and applies the txnkv disposition.
Immediate resends preserve the same remaining ranges. Rebuild re-locates only
the failed task's remaining ranges through the shared cache and prepends the
one-or-more replacements without changing later tasks. It uses
a response-owned map of per-region backoff budgets and checks cancellation
before mutation, sleep, PD work, and dispatch. The same region shares one
budget across resend and rebuild; a split region ID receives its own budget.
Lock and unsupported region branches remain typed terminal/fail-closed
outcomes.

Finally integrate the three worktrees, delete terminal/no-retry assertions,
run focused translated tests, and add one process-coordinated TiUP proof. The
runner must wait for explicit phase markers rather than fabricating routes.

## Validation and Acceptance

Wire tests must prove exact field numbers and nested leader/current-region
round trips. Table tests must cover every outer region-error branch in pinned
client-go handler order, including messages with multiple populated fields. Cache tests
must cover known/missing leaders, leader outside the exact region, epoch ahead,
split, merge, empty current regions, removed stores, store-address change, and
stale delayed observations.

Retry tests must prove no successful state mutates before a full accepted
response; known-leader immediate resend; bounded no-leader and busy backoff;
one-to-many rebuild; preservation of prior successful pages and untouched
later tasks; no duplicate future tasks; exact logical order; one shared budget per region ID across both
retry levels; independent split-region budgets; cancellation before cache
mutation and during sleep; terminal branches; lock fail-closed behavior; and
close/exhaustion ownership.

The live proof passes only when the same Rust process performs:

    seed PD -> discovered PD member -> RegionCache -> old TiKV leader
            -> surviving PD member -> NotLeader(new leader)
            -> RegionCache update/rebuild -> new TiKV leader

The runner must prove the removed PD endpoint is unreachable, the PD leader and
region leader identities changed, the Rust-selected endpoints match discovered
survivors, a structured TiKV response was received after the changes, and all
owned processes, registry entries, tag directories, and service endpoints are
gone during cleanup.

## Idempotence and Recovery

All focused tests and ledger checks are deterministic. Each live run uses a
process-specific TiUP tag and ports, records every owned process, and refuses
occupied endpoints. Phase files live under the run-owned directory and are

receipt. A failed feature is repaired in its declared worktree; do not create

## Interfaces and Dependencies

`tidb-pd-client` owns member discovery and direct endpoint selection only.
`tidb-txnkv` consumes that loader capability, owns protobuf-to-neutral topology
conversion, cache mutation, route selection, and region backoff arithmetic.
`tidb-distsql` consumes only neutral txnkv recovery dispositions and owns query
task ordering. Neither DistSQL nor executor may import PD/tonic types or retain
a second mutable topology authority after a disposition is applied; immutable
attempt-local route snapshots remain necessary to reject stale responses.
