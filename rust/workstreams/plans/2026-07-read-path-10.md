## Purpose / Big Picture

Campaign 10 removes the shell-fabricated topology seam left by Campaign 09.
After this campaign, a caller can give the Rust read path one plaintext PD
endpoint. Rust obtains the cluster identity, region boundaries, epoch, leader
peer, and TiKV store address through the exact pinned PD gRPC methods, partitions
the request across the discovered regions, and reaches TiKV through the existing
real Coprocessor RPC leaf.

The observable exit is a pinned TiUP test whose runner exports only the PD
address. No Python or environment variable supplies region, peer, store, or
TiKV-address metadata. This is a bounded PD-backed read route, not production
PD parity: endpoint refresh, failover, TLS, router service, keyspace-v2 codecs,
retry/backoff, lock resolution, and COM_QUERY remain explicit later work.

## Surprises & Discoveries

- Observation: Campaign 09 created a real `RegionCache<RegionLoader>` but the
  checked DistSQL path does not consume it.
  Evidence: `tidb-txnkv/src/region/cache.rs` owns loader-backed misses, while
  `direct_unary_query_transport.rs` consumes constructor-injected
  `ResolvedRegionRoute` and address maps. The live runner builds those maps
  from PD HTTP responses in Python.
- Observation: the pinned PD module is a separate source/test universe.
  Evidence: both TiDB and client-go pin `github.com/tikv/pd/client` at
  `v0.0.0-20260708075407-4e05b9d2c2d3`; it contains 58 production Go files,
  28 test files, 319 declarations, and 156 runnable obligations.
- Observation: the module has no direct original unit test for `GetMembers`,
  `GetRegion`, or `GetStore` behavior.
  Evidence: the closest narrow module runner is `opt.TestOptions`; therefore a
  source-derived mock PD server and live TiUP proof are mandatory.
- Observation: the existing Rust direct-unary test already dispatches one
  request across two ordered regions.
  Evidence: `direct_unary_client_runtime_source.rs` must not regress to a
  single-region-only transport merely because the first concrete PD loader is
  bounded to one endpoint.
- Observation: deleting the static constructor also makes the Campaign 09
  static-topology live test uncompilable.
  Evidence: Campaign 10 therefore owns atomic retirement of both
  `realtikv_tikv_unary.rs` and `run-campaign09-realtikv.sh` alongside their
  PD-only-input successors; no compatibility constructor is retained.
- Observation: deleting the duplicate request sender would leave two pinned
  client-go evidence rows pointing at retired Rust artifacts.
  Evidence: the transfer validator now accepts qualified external-module
  anchors, and Campaign 10 atomically moves only `region_request.go` and
  `TestRegionRequestToSingleStore` to the sole DistSQL route owner.
- Observation: the first integrated draft could perform PD I/O before rejecting
  unsupported DAG/store metadata, treated removed-store headers as fatal, and
  narrowed unknown peer-role discriminants.
  Evidence: adversarial review produced focused regressions for pre-PD request
  validation, a healthy leader with a removed follower, and raw role `99`.
- Observation: a cleanup proof based on one early descendant snapshot and the
  PD port alone could miss a later or reparented TiKV process.
  Evidence: the runner now refreshes tag-owned PIDs during teardown, requires
  successful `tiup clean` and registry reads, and checks both PD and TiKV ports
  before deleting its tag directory.

## Context and Orientation

The pinned PD module is resolved from TiDB `go.mod` and the local Go module
cache. Its source client learns cluster identity through `GetMembers`, then
sends that identity in `pdpb.RequestHeader` for `GetRegion` and `GetStore`.
The minimum dependency-closed protobuf surface is `pdpb` request/response
headers, errors, members, region and store calls plus `metapb` region, epoch,
peer/role/witness, store state, node state, and address fields.

`tidb-txnkv/src/region/cache.rs` is the Rust metadata cache. A `RegionLoader`
loads the region containing one encoded key. Campaign 10 extends that stable
contract with nonzero cluster identity and typed load failures, then adds a
concrete PD-backed implementation. `tidb-distsql` must own the cache because it
owns request-range partition and logical response order. A range walker starts
at each requested start key, loads the containing half-open `[start,end)`
region, advances to that end key, and stops only when the requested end is
reached or the final unbounded region is reached. A repeated or backward
boundary is an error, never a loop.

Campaign 09's `TonicCoprocessorClient` remains the TiKV data-plane leaf. The PD
client is a control-plane leaf and must not leak tonic details into DistSQL or
executor crates.

## Plan of Work

First replace the hardcoded client-go inventory generator and filenames with
one external-module ledger that scans both pinned modules offline. Preserve all
current client-go ownership rows byte-for-byte in meaning, add PD-client rows
as `UNTRIAGED`, and make queue/dashboard/gate code consume the consolidated
files.

Next freeze two parallel feature slices. The PD slice owns the checked
`metapb`/`pdpb` projections, a separate `tidb-pd-client` control-plane crate,
the `tidb-txnkv` PD adapter, source-derived mock-server tests, and the live
TiUP proof. The DistSQL successor owns the prior direct-unary TiDB source/test
obligations, `RegionCache` range walking, the live route consumer, executor
compatibility tests, and deletion of the replaced static topology and duplicate
context-attachment path. Shared Cargo/protobuf exports and the stable loader
trait are frozen before claims so worktrees do not collide.

The PD client bootstraps once with `GetMembers`, rejects missing/zero cluster
identity, and sends the exact cluster ID on each region/store request. It
rejects transport timeouts, PD header errors, cluster mismatches, missing
region/epoch/leader, leader-not-in-peers, removed/tombstone stores, mismatched
store IDs, empty addresses, invalid endpoints, and malformed protobufs with
typed errors. It performs no retry.

After both slices integrate, replace the Campaign 09 runner's Python topology
extraction. The live Rust test receives only `C10_PD_ADDR`, discovers the
route, and reaches the TiKV Coprocessor method. Teardown retains the strict
owned-process, registry, directory, and PD-endpoint checks added in Campaign
09.

## Validation and Acceptance

Mock PD tests must assert exact gRPC paths, empty bootstrap request semantics,
nonzero cluster identity, request headers, region keys, store IDs, all peer
roles and witness bits, source store-state handling, raw timeout/transport
identity, and exactly one attempt. Negative responses must fail before any TiKV
call.

DistSQL tests must prove a cache miss loads once, a subsequent hit does not call
PD, two contiguous regions preserve ordered TiKV dispatch, an unbounded final
region terminates, overlapping input ranges do not duplicate region loads, and
malformed or non-progressing boundaries fail closed. PD discovery may happen
when the query response is bound, but the TiKV RPC remains lazy until the first
pull. Cluster ID, epoch, peer, and address must have one PD-backed authority.

The live test passes only when the chain is:

    PD gRPC -> RegionLoader -> RegionCache -> DistSQL -> TiKV Coprocessor

It must receive a structured TiKV application response and prove that no
Campaign 10 process, registry entry, tag directory, or PD endpoint survives.
That response proves transport and routing, not table rows.

## Idempotence and Recovery

Ledger generation and focused tests are deterministic and safe to rerun. Each
TiUP run uses a process-specific tag and refuses an occupied PD port. Its trap
must retain ownership metadata when a child remains alive, and remove residual
data only after all captured descendants and registry signals are gone.

Claims are released only with a matching integration receipt. If a worktree
fails, leave its claim active, repair the same declared paths, and rerun the
focused gate; do not create an overlapping replacement claim.

## Interfaces and Dependencies

The stable loader contract in `tidb-txnkv` is:

    pub trait RegionLoader {
        fn cluster_id(&self) -> u64;
        fn load_region(
            &mut self,
            key: &[u8],
        ) -> Result<RegionLocation, RegionLoadError>;
    }

The concrete PD client belongs below `tidb-txnkv` in a separate
`tidb-pd-client` crate. It depends on `tidb-proto`, tonic, prost, tokio, and
bytes. `tidb-txnkv` converts its wire-neutral region/store results into
`RegionLocation`. `tidb-distsql` depends only on the `RegionLoader` capability
and must not import tonic or `pdpb` types.
