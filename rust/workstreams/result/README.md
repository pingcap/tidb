# Result Workstream

Owns expression and seed-executor result equivalence. Its source obligations
come from Go expression/executor tests plus the paired `t/*.test` SQL inputs
and `r/*.result` expected outputs, with `query_diff`, `expr_diff`, and
`table_diff` as differential rings. Each agent owns one domain implementation
and its source-derived corpus; golden files are generated by the Go helper and
never hand-written.

The shared scalar/context seam is owned by the datatype/context steward. Result
workers consume `tidb_datatype::Datum` and `tidb_expr::EvalContext`; they must
not introduce a second value enum, charset registry, warning channel, or
context-free semantic path.

The sole-`Datum` migration has landed. Typed expression construction and the
full statement-scoped `EvalContext` are still incomplete. If current field
metadata, session state, collation, warning state, or catalog cannot represent
a Go behavior, extend the stewarded seam from Go source or report the boundary
and return `Unsupported` before mutation. Do not infer a string signature from
runtime `Datum`, and do not approximate output to make a corpus pass. The
living migration plan is
`execplans/2026-07-15-datum-eval-context.md`.

The bounded `tidb-exec::result_field_resolver` ports the dependency-closed
table-less part of `pkg/executor/adapter.go`: expression display names,
aliases, qualified column names when an authoritative type hint is supplied,
and literal/operator/function type metadata. The adjacent `result_schema`
leaf now binds a single-table projection and wildcard to declared catalog
`ColumnType` metadata, and `result_schema_multi` extends that boundary to
bounded inner/CROSS/comma/LEFT relation trees, aliases, qualified paths, and
self-join declaration order. `result_schema_join_output` consumes already
resolved child fields to port planner output order, LEFT-side nullability, and
USING coalescing metadata. The automatic server path now consumes this
resolver for `SELECT` INNER/CROSS/LEFT/USING catalog joins, including row null
extension and coalesced output order. Neither path may infer a type from
runtime `Datum`; the isolated projection contract now supplies automatic
metadata for direct columns, aliases, and qualified/bare wildcards while
`Database::project_row` remains the sole row-value owner. General planner
ON/USING typing, full executor output-name derivation, and record-set lifecycle
remain open. The projection leaf rejects hidden redundant USING columns and
untyped expressions.

`join_predicate.rs` is the adjacent execution leaf for direct cross-side
column equality in `ON` and `USING`: it binds only unique opposite-side
columns, shares three-valued NULL non-match semantics, and falls back to the
existing evaluator for literals, expressions, ambiguity, or compound
predicates. Hash/index join algorithms, outer-row status propagation, and the
full planner predicate type system remain outside this bounded owner.

The planner-owned `join_condition` classifier is the source-backed sibling
for qualified/unqualified cross-side `=`/`<=>` and USING binding. It returns
explicit unsupported/ambiguous outcomes for compound predicates rather than
silently routing them through a value-only guess.

`tidb-planner::residual_condition` now retains residual AND/OR/NOT structure
and syntax-only scalar/function metadata with deferred evaluation. It does not
perform typed coercion, predicate pushdown, or join execution.

`tidb-planner::condition_binding` is the next hand-off: known column paths are
resolved into source-ordered `FullSchema` indices, while dedicated predicates
remain opaque and deferred. No Datum evaluation or physical join algorithm is
claimed by this boundary.

`tidb-planner::predicate_partition` is the follow-on routing leaf. It
conservatively classifies bound predicates as left/right pushdown, join
residual, constant candidate, or typed-deferred work, and marks routes that
require a real typed evaluator. It deliberately does not evaluate `Datum`
values, rewrite plans, or choose a physical join algorithm.

`tidb-planner::typed_condition` is the executor handoff for that deferred work:
it records child-filter, join-filter, or outer-match mode, source `FullSchema`
width, and whether the caller must keep UNKNOWN distinct from FALSE. It is a
request contract only; typed Datum evaluation, row materialization, null-status
mutation, and join execution remain separate owners.

`tidb-exec::evaluate_typed_condition` is the first scalar consumer of that
request. It validates the captured `FullSchema` width, evaluates existing
`Datum` values, and returns TRUE/FALSE/UNKNOWN without applying filter policy
or mutating outer-row status. Vectorized batching and join lifecycle remain
open.

`evaluate_typed_condition_batch` now exposes the dependency-closed batch part
as disjoint row-indexed TRUE and UNKNOWN masks with indexed failures. It does
not reuse Go selection slices, execute vectorized expression kernels, mutate
outer-row status, or materialize join results.

`transition_outer_row_status` applies those masks to a pure
`Unmatched`/`Matched`/`HasNull` status vector with length validation. It mirrors
the per-batch `filterAndCheckOuterRowStatus` transition. The pure
`merge_outer_row_status` layer now preserves cumulative precedence across
candidate batches (`Matched` > `HasNull` > `Unmatched`) with length validation;
`select_outer_row_statuses` also returns source-order TRUE indexes aligned with
their statuses while leaving the full FALSE/UNKNOWN status slice available;
`finalize_outer_row_statuses` emits source-order events only for unmatched or
UNKNOWN rows and exposes the default-inner/UNKNOWN signals; row lookup,
selection/chunk reuse, null extension, and physical join output remain open.
`PredicateBatchBuffer` now owns reusable TRUE/UNKNOWN slice reset, replacement,
capacity retention, and row-count validation; it does not run vectorized
kernels or copy rows.

The dependency-closed `tidb-exec::statement_status` leaf ports the
source-shaped statement counters, warning ordering/cap, explicit
last-insert-ID state, retry/full reset, DML/DDL/SELECT/session publish
policy, and the separate `ExecSuccess` publication bit. `cluster.rs` now
attaches that state to the shared Session's begin/evaluate/retry/finalize
boundary; `Session::render_exec_error` hands the exact failed status snapshot
to `RenderedExecError` while preserving caller-rendered bytes, and explicitly
detaches parse/framing failures from a prior statement. Its adjacent
`status_result` leaf converts an already published status losslessly into
protocol `OkPacket` and `ResultSetOptions` without reading runtime `Datum`
values. The pure `tidb-exec::error_context` leaf now owns the fixed Go
`ErrGroup` level map, source flag precedence, and typed return/warn/ignore
disposition; warning producers, live session attachment, SQL-mode derivation,
planner join execution,
and server wire writes remain open; `tidb-exec::error_conversion` only maps
an already-rendered `ExecError` to the protocol error-kind descriptor and does
not synthesize messages.

Builtin ownership follows the authoritative Go source family, not a growing
generic match. For example, all currently translated behavior from
`pkg/expression/builtin_time.go` lives under `tidb-expr/src/time_fn/`, including
its internal calendar algorithms, pure duration/date functions, fixed-clock
functions, and focused source tests. `func.rs` contains only the one narrow
family dispatch. New time behavior extends that directory and its Go-derived
corpus; it must not recreate `builtin_ext/time2.rs` or clock helpers in the
root dispatcher.

The control-family leaf now carries representable source rows for both
`TestIfNull` and `TestCoalesce` under `tidb-expr/src/tests/control.rs`.
`COALESCE` currently preserves first-non-NULL scalar values, while Go's
FieldType-driven mixed numeric promotion and typed temporal/JSON/SET/error
rows remain explicit `PARTIAL` evidence until the shared context supports
those types. Do not add runtime-datum heuristics or eager-evaluation
workarounds to close those rows.

The bounded `IF` scalar leaf follows `builtinIf*Sig` in
`pkg/expression/builtin_control.go`: its condition uses the source's wrapped
`EvalInt` coercion (including numeric-prefix strings) and only the selected
branch is evaluated. Direct rows cover the scalar integer/NULL/decimal/real
and string table plus both lazy division-by-zero guards. Go's FieldType result
promotion, typed temporal/duration/JSON/vector signatures, function-class
construction, and warning/session state remain explicit `PARTIAL` boundaries;
do not replace the source coercion with a runtime `truthy_of(String)` guess.

The bounded `CASE` scalar leaf follows `builtinCaseWhen*Sig` in the same Go
control source. Direct rows cover every scalar/NULL/real truthiness case from
`TestCaseWhen`, written-order first-match selection, lazy dead branches, and
the unreachable JSON result row. A selected JSON result, the injected Go
`error` condition, FieldType-driven result promotion, and function-class or
session state remain explicit `PARTIAL` boundaries; do not force unsupported
typed branches merely to make the value-only evaluator claim full coverage.

The LIKE audit keeps the existing physical matcher as the sole scalar owner
and verifies it against Go's `CompilePattern`/`DoMatch` behavior. Direct
regressions cover custom escape bytes, disabled escaping, trailing escapes,
NULL operands, numeric stringification, and wildcard backtracking. The
vectorized allocator and warning/error channels remain explicit `PARTIAL`
boundaries rather than duplicated evaluator paths. `like_match_with_collation`
now also ports the source wildcard callback for all registered general-CI and
Unicode-CI weights, including `ß`/accent folding and the supplementary-rune
boundary; the 0900-ai-ci column remains a deliberate registry boundary.

The ILIKE scalar leaf follows the same ownership rule. `like::ilike_match`
ports Go's ASCII-only lowercasing, including the escape-preserving
`LowerOneStringExcludeEscapeChar` state machine, before reusing the existing
binary wildcard matcher. The complete `TestIlike` scalar table is direct Rust
evidence, including lower/upper custom escapes, escaped marker runs, Unicode
characters, and wildcard rows. Go's function-class/pattern-cache lifecycle,
chunk/vectorized paths, session-selected collations, and warning/error channels
remain explicit `PARTIAL` boundaries; no second matcher or runtime-datum
collation heuristic is allowed.

The bounded `FIELD` scalar leaf follows `fieldFunctionClass` and its three Go
signatures in `pkg/expression/builtin_string.go`. It selects one comparison
mode for the complete argument list before scanning: ETString for all-text
values, ETInt for all-integral values, and ETReal for mixed/decimal/real values.
This preserves the source's easily missed rule that a later numeric argument
forces earlier string candidates through numeric-prefix conversion
(`FIELD('1', '01', 1)` returns position 1, not position 2 from pairwise text
comparison). The FieldType/function-class construction, session collation and
warning state, and vectorized execution remain explicit `PARTIAL` boundaries;
do not reintroduce a runtime pairwise type heuristic.

The scalar operator leaf follows `pkg/expression/builtin_op.go`'s ETInt/ETReal
construction for shifts, bitwise operators, unary `NOT`, `IS TRUE`/`IS FALSE`,
and logical operators. A shared numeric-prefix truthiness helper keeps string
and raw-byte values consistent across those contexts, including malformed text,
`'0.3'`, NULL, and the representable decimal/real rows. Typed duration/time/
JSON values, FieldType construction, warning/session state, and vectorized
execution remain explicit `PARTIAL` boundaries; do not fork a second operator
coercion path.

The bounded REGEXP_LIKE scalar leaf uses one source-shaped `regexp_like`
builder. It preserves Go's empty-pattern and malformed-pattern errors, the
`i`/`c` rightmost precedence, and RE2 `m`/`s` flags through typed builder
options. Session-selected collations, context-keyed regexp caches, warning
channels, chunk/vectorized execution, and REGEXP_SUBSTR/INSTR/REPLACE remain
explicit `PARTIAL` boundaries until the shared evaluator context can model
them; do not add a second regex path or fake cache adapter.

The original two-argument `[NOT] REGEXP` rows in
`pkg/expression/builtin_like_test.go:64` use that same production builder but
also have a parser-dispatch ring. All nine successful source vectors and both
negated forms run through `Expr::Regexp`; the four malformed patterns are
checked at the leaf boundary, including Go's lone-backslash failure. This
keeps the older operator from silently becoming a `REGEXP_LIKE`-only port;
function-class/session collation, vectorized execution, and warning/error
channels remain the same explicit `PARTIAL` boundaries.

The ranking window leaf follows the source-owned executor functions in
`pkg/executor/aggfuncs/{func_rank,func_percent_rank,row_number}.go`. The seed
executor's `ROW_NUMBER`/`RANK`/`DENSE_RANK`/`PERCENT_RANK` ring keeps stable

reuses the same typed `ORDER BY` comparator as sorting rather than Rust enum

boundaries; do not add a second ranking implementation for those concerns.

The integer DIV/MOD leaf follows the four source signatures in
`pkg/expression/builtin_arithmetic.go`. Mixed signed/unsigned DIV delegates to
the same checked quotient rules as `DivInt64`, `DivUintWithInt`, and
`DivIntWithUint`; MOD uses the dividend's sign and only the left operand's
unsigned result flag. Decimal/real arithmetic, session warning policy, and
function-class/vectorized type state remain explicit `PARTIAL` boundaries until
the shared evaluation context can represent them.

The bounded `INTERVAL` scalar leaf follows `intervalFunctionClass` plus the

The LEAST/GREATEST scalar leaf shares `compare2`'s source-owned value path.
Mixed signed/unsigned integer extrema retain the DECIMAL result domain, while
the Go string signature is now preserved when any argument is textual: numeric

The bounded `TestCompare` scalar leaf keeps the source's mixed numeric

The ABS leaf follows `builtinAbsIntSig`'s signed `BIGINT` boundary: the one
value without a positive `i64` representation (`math.MinInt64`) returns the

`PARTIAL` boundaries.

The integer TRUNCATE leaf also preserves the source FieldType boundary for an
unsigned scale. `builtinTruncateIntSig` and `builtinTruncateUintSig` return the
integer input unchanged before interpreting the scale value, so a value such as
`CAST(18446744073709551615 AS UNSIGNED)` cannot be narrowed to a signed

owner; function-class metadata, warning policy, and vectorized execution remain
explicit `PARTIAL` boundaries.
