# Parser Workstream

Owns source-faithful tokenization, AST construction, canonical SQL restore,
and parse-error behavior. Its oracle is the static Go parser golden in
`difftests/corpus/coverage/integration_parser_golden.tsv`; its queue is
generated by `integration_parser_queue`.

`difftests/corpus/coverage/evidence/parser/<source-stem>.tsv` is the physical
ownership unit for one top-level `pkg/parser/<source-stem>.go` source. A feature
agent updates only that fragment, then runs the agent-local structural gate:

```sh
cargo run --locked -j 12 -p difftest --bin parser_translation_manifest -- --check-fragments
```

The evidence steward regenerates the canonical manifest and summary with
`--write`; `--check` byte-compares both generated artifacts. `partial` remains
an implementation obligation; only a complete source and original-test audit
can move a row to `ported`.

Feature ownership is one statement-domain module, matching parser tests, and
one focused selector or corpus. A parser feature must read the Go grammar/AST
restore/tests first, prove its selector against the checked Go golden, and
make unsupported executor behavior explicit rather than faking catalog state.

Do not edit the AST/parser routing roots concurrently. Request a steward
landing with the exact Go rule and typed Rust interface when a new statement
variant or first-keyword route is required.

The `parser-partition-key-algorithm-source-wave` leaf owns the four original
`TestPartitionKeyAlgorithm` rows: `LINEAR KEY ALGORITHM = 1` restores with its
column list, while `-1`, `0`, and `3` are rejected at parse time. It reuses the
existing typed partition method and does not claim partition execution or the
remaining `ddl_partition_parser.go` source obligations.

The `parser-interval-partition-source-wave` leaf owns all 13 original
`TestIntervalPartition` rows. `RANGE ... INTERVAL (...)` expression and
`COLUMNS` forms restore with their optional `FIRST`/`LAST` bounds and
`NULL`/`MAXVALUE` markers, while the interval-specific ALTER split/merge and
boundary rows preserve Go's accepted/rejected behavior. Broader partition AST,
semantic validation, executor, and integration obligations remain explicit
`PARTIAL` boundaries.

The `parser-index-hint-source-wave` leaf closes the Go hand-parser's quoted
index-name token boundary: `USE INDEX ('idx')` is accepted and restored with
the canonical backquoted index name `idx`, while identifier/keyword names
continue through the existing typed hint parser. The broader `TestIndexHint`
table, optimizer application, catalog validation, and execution semantics
remain explicit `PARTIAL` boundaries.
