# Go master drift register

Unresolved Go master changes since the branch's merge-base (b94006d3abf, 2026-07-10). Unresolved only: a row leaves when its change is ported or proven present.

Candidates come from `tidb-wt/tools/drift/audit.py`: each non-merge Go master commit touching non-test `pkg/` code (parser excluded) whose added string literals and new func/type/const names are mostly (>= 50%) absent from `rust/`. A candidate is not proof; its count is missing/total tokens. Regenerated 2026-11-27 against gomaster e722f8f1541: 208 flagged, of which the Held list below and the verified gaps are taken out.

A second, function-level list: `python3 -I rust/scripts/go-func-drift.py ../gomaster` names each Go master commit that changed a Go function some Rust file ports (by its ``Go `Name` `` citation) and that no Rust commit message cites, with the Rust files to revisit. A drift port's commit message cites the Go SHA; that citation is what takes the commit off both lists.

## Verified gaps

- b82bed1eca2 / cfb54f9e87c remainder: Go's pre-Open `checkMaxExecutionTimeExceeded` (Rust's watchdog clock starts at executor build), `NormalizeStmtCancellationError` (finishStmt, recordSet.Next) and the non-batch cop request's deadline cause (Rust answers the transport's deadline text, Go `ErrMaxExecTimeExceeded`).
- 47dc1214658: `tidb_redact_log` defaults ON (OFF in test builds). The default alone makes Rust's internal sessions redact plan text (restricted EXPLAIN, EXPLAIN EXPLORE, MV refresh EXPLAIN print `?`). Go keeps them literal through `rebuildSysVarCache` running every `SetGlobal` hook on a borrowed pooled session, `planGenerator.Generate` taking the caller's mode, and tests setting `EnableRedactLog = Off`. Blocked on Rust having no `sysSessionPool` reuse (`open_system_session` builds a fresh session per internal statement).
- 35232111b23, dc52119f4a5: NextGen starter privilege reset and the redacted global-variables API.
- Bootstrap upgrade steps stop at version 263; every later master upgrade step (`upgradeToVer318` of 93a01d31f6d among them) is unported.
- COM_CHANGE_USER is unimplemented (answers 1047), so 6c869bc1432, 1bcfcd48663, e5efa812b7c, f1be26c3f1c have nothing to land on.
- 25050b53f84: needs storage constructors that may fill or clear the backend's credentials (`SendCredentials`).
- 6775607e08c: a parser grammar change the Rust parser takes from the Go hparser branch.
- ab7355f7981 (rest; its affinity cleanup, job-step state restore, flashback order and multi-schema diff are ported): Rust has no `handleUpdateJobError`, so a job row too large to write (`kv.ErrEntryTooLarge`) neither cancels the job nor cleans up its affinity groups; the `afterAsyncNotifyEvent` failpoint and the storage-class half of `checkpointStorageClassTransitionStep` have no Rust site.
- Placement bundles and label rules are sent to PD at commit time (`real_tikv_ddl` delivery), so a PD refusal retries the step where Go's `onCreateTable` / `onTruncateTable` cancel the job.
- 7193401b674 (keyspace half; SHOW AFFINITY's lookup of only its groups is ported): NextGen affinity group ids (`_tidb_ks{id}_...`) and keyspace-encoded group key ranges. The DDL job steps have no keyspace codec: label rules use `CodecV1` too, so both are keyspace-unaware under NextGen.
- fe1f4b41b44: the warning-only check that the advertised status endpoint (`advertise-address` + status port `/info`) answers this TiDB's `ddl_id` (`pkg/server/internal/advertisedstatus`) is unported.
- Index row-count estimation over an appended handle (one batch, whole functions: Go `deriveIndexPathStats`/`pruneEstimateRange` in `core/stats.go` and `cardinality/row_count_index.go`): 12d24af9894, 94b834d94b6, 70cff7d9f66, 38d990578c4 and later. Rust still estimates with July's `pruneEstimateRange` (exclusivity kept, no union); gomaster probe for `tests_explain.rs` `truncated_handle_estimate`: `a=5 AND id>10` 10.00 (Rust 12.50), `id<10` 10.00 (12.50), `id IN (11,22)` 2.00 (20.00), `id=7` 1.00 (10.00); unsigned handle 10.00 (same).
- TRUNCATE TABLE does no `preSplitAndScatterTable` (Rust pre-splits only at CREATE TABLE, in the executor).
- c09f6278deb: needs hypothetical expression indexes, which Rust refuses.
- c767f6fd8c0: the storage-class transition manager is unported, and with it 56ee5bb2684's transition-completion half and 64e8c4c05ec.
- 03148cd4adf: the lightning config messages are unchecked (the objstore half is ported).
- EXPLAIN ANALYZE of DDL is refused ("not supported yet"); Go runs the DDL.
- Point get / batch point get have no `singlePartID`: a global-index point read under static pruning does not check the pruned partition.
- `PointGetPlan.PrunePartitions`' `_tidb_rowid` + one PARTITION arm: Go plans a TableDual when that partition is DDL-ignored; Rust keeps a Point_Get.
- Go `ddl/mockDMLExecution` in `addIndexTxnWorker` / `cleanUpIndexWorker` `BackfillData` has no Rust injection site, so Go tests driving DML mid-backfill (`TestGlobalUniqueIndexDeleteGuardAfterValidatedExchange`) cannot be ported.
- Go `db_partition_test.go`'s global-index-during-DDL tests `TestGlobalIndexLookUpInDropPartition`, `TestGlobalIndexUpdateInTruncatePartition` and the rest are unported; `checkGlobalIndexCleanUpDone` (a raw index KV scan) has no test-side counterpart.
- Deliberate divergence: GRANT ... REQUIRE TOKEN_ISSUER alone stores `{}` where Go stores `''` (Go then fails SHOW CREATE USER and panics in SHOW GRANTS); both load as REQUIRE NONE.
