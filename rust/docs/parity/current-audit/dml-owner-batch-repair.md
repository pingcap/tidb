# Shared DML metadata batch

This is connected maintenance of existing A01/E02/E03 owners from Cloud commit `40ee71600bff5dccce1102a97126e85ed0a870ec`, compared with Go master `93a01d31f6da205ae4bf376825293903a6899fdb`. It does not accept a complete upstream package or all eight B02 findings. Counts remain **86 tracked, 29 repaired, 57 unresolved (39 open, 18 partial)**. Other findings retain their earlier evidence; they were not all behaviorally reproduced in this batch.

Joined storage-backed UPDATE/DELETE now obtain source shape from the logical planner without opening the row source. Derived/view/LATERAL inputs are metadata during planning; sequence values are consumed only during execution. Authorization, EXPLAIN and FK plan construction resolve the same outer write targets. A nested derived-query alias cannot become an outer DELETE target. Unqualified DELETE follows Go's single `popVisitInfo` rule when WHERE and ORDER are absent.

Joined writes now populate FK plan nodes through the shared DML allocator. UPDATE columns union across aliases by physical table ID, checks precede cascades, untouched FK columns produce no trigger, and foreign_key_checks=0 disables them. The runtime's existing shared FK checks/cascades remain active. Removed code comprises the Session DELETE AST target resolver and the KV materializing layout switch. Matrix execution remains because its row identities have not migrated.

The grouped tests also exposed two retained failures. Go `onCreateForeignKey` allocates an ID before checking existing rows; `dropForeignKey` removes the failed constraint without decrementing that ID. Synchronous ALTER staging now preserves that high-water mark by physical identity on failure, while retaining rollback of constraints/indexes/data. Go `Parser.ParseOneStmt` validates trailing statements then returns ErrSyntax (1149) for more than one: Rust now enforces that boundary instead of silently returning the first AST. The old 1064 cardinality assertion was corrected to Go's exact 1149 message; malformed SQL still asserts 1064 and positional diagnostics. Neither meaningful failure was deleted.

For a source-less correlated LATERAL query, TopN pushdown could put LIMIT over a zero-column Selection/TableDual and fail the shared ColumnPruner invariant. A conservative guard keeps LIMIT above the projection producing its columns. This is a Rust correctness guard, not a claim that Go has the identical additional guard or that the full optimizer package is accepted. The invariant and side-effect regression remain enabled.
