### Structure: Go's shape before more ports

| ID | Status | Remaining gap | Go owner |
| --- | --- | --- | --- |
| S01 | open | Builtins reach session state through hand-built hooks (a method on `tidb_exprctx::Columns`, a field on `StmtContext`, a method on the executor's builder trait, a session implementation) instead of Go's optional eval-property providers: Go's `session.go` builds `sessionexpr.NewExprContext`, which installs the KV-store, infoschema, privilege-checker, session-vars, SQL-executor, sequence, advisory-lock and DDL-owner providers that builtins read (`builtinTiDBMVCCInfoSig` embeds `KVStorePropReader` / `PrivilegeCheckerPropReader`). `tidb-sessionexpr` and `tidb-expropt` port them, but the live session never builds that context. A consequence: `StmtContext` computes the PROCESS privilege for every statement, where Go asks the privilege checker only when `TIDB_DECODE_SQL_DIGESTS` is built or evaluated | `pkg/expression/sessionexpr`, `pkg/expression/expropt`, `pkg/session/session.go` |
| S02 | open | `TableCommon` keeps the public columns and the non-public (adding or changing) columns as two lists, and an index's `column_offsets` index whichever list it was loaded against (public for a public index, public then non-public for a non-public one). Go's `TableCommon.Columns` is every `tblInfo.Columns` entry in metadata order, `Cols()` / `VisibleCols()` / `WritableCols()` / `DeletableCols()` are slices derived from it, and `IndexColumn.Offset` always indexes `tblInfo.Columns`; the two bases caused the MODIFY COLUMN mutation-checker panic | `pkg/table/tables/tables.go` (`TableCommon`, `initTableCommon`) |
| S03 | open | DDL and reorg errors lose their Go identity on the way to the job: `ClusterDdlError::Backfill(String)` drops the code, and `DdlPlanError::Encode` stands for Go's plain `errors.New`, so `is_retryable_job_error` tells a plain error from a `*terror.Error` only through that variant. Go keeps one `err` whose cause `isRetryableError` type-checks (`*terror.Error` with a retryable code, else any plain error retries). | `pkg/ddl/job_worker.go` (`isRetryableJobError`), `pkg/ddl/index.go` (`runReorgJobAndHandleErr`) |
| S04 | open | Only the distributed (DXF) reorganization runs as Go's `runReorgJob` does (`DistReorgSlot`: `reorgFn` on its own thread, each step waiting on `doneCh` until the progress tick); the local backfill still runs inside the step against a cooperative deadline (`BackfillExecutor::deadline`). Go runs every `reorgFn` asynchronously under the job's `reorgCtx` | `pkg/ddl/reorg.go` (`runReorgJob`, `reorgCtx`) |
| S06 | open | No Go `Domain.Close`: a node's DDL (its etcd owner manager, schema syncer and workers) stops only in `Drop` when the last `Arc` of the domain goes, and no shutdown path closes it explicitly. A process that still holds a reference never revokes its DDL owner lease, so the next node waits out the owner TTL (60s) before it can own DDL: each realtikv test waited about 45s for the previous test's owner until the harness closed the owner manager itself, as Go's harness does (`ddl.CloseOwnerManager`). The server's shutdown relies on the same `Drop`. Go's `Domain.Close` calls `ddl.Stop` (owner `Cancel`, etcd session close), and the DDL owner manager is the store's global one (`ddl/owner_mgr.go`). | `pkg/domain/domain.go` (`Close`), `pkg/ddl/ddl.go` (`Stop`), `pkg/ddl/owner_mgr.go` |
