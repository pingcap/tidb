The grpcutil review revealed a prerequisite defect: its UnaryBackofferInterceptor
copies the supplied backoffer by value for every RPC. The native callback could
not be copied, while unsigned timing and saturation restricted the source value
domain. The earlier retry receipt documented some restrictions but still claimed
complete acceptance. This receipt corrects that claim and revalidates the whole
package after removing those differences. It does not claim a complete grpcutil
owner or activate a partial interceptor.

## Changes and removals


Backoffer now copies every scalar configuration/execution field through Clone and
shares only the checker function's captured environment through Arc. The existing
Box-accepting checker setter remains available. Resetting or replacing a checker
on one copy cannot reset or replace another copy. An attached backoffer can be
copied under its existing short mutex guard, then executed independently, matching
Go's `newBo := *bo` without sharing an execution lock across RPCs.

All duration inputs/state use signed i64 nanoseconds and attempt counts use isize.
Constructor conditions, interval doubling, accumulated waits/log time, attempt
increments and budget subtraction retain Go's signed wrapping. Only positive
total budgets and log intervals activate their checks. Non-positive timer delays
are immediately eligible; non-positive ticker intervals panic before examining
the attempt count. Non-positive fixed retry counts execute no operation. Existing
lazy timer reuse, cancellation/error identity, dropped-future reset and ticker
phase behavior remain covered.

Reusable constructor options are applied after normalization in source order.
The public Rust-only with_min_log_interval builder is removed; Go's private
logging option remains private test support. The unsigned Duration::MAX
saturation assertion is removed because it specifies Go-absent behavior; all
original valid cap/normalization cases and other regression assertions remain.
Default initialization directly passes the source signed retry count and still
uses its one-second interval. The options package's backoffer fixture migrates.

These are source/API changes: external Rust callers must supply signed nanoseconds
instead of std::time::Duration, and fixed retry count is isize instead of usize.
There is no new dependency, lockfile change, worker, transport retry loop or
request mode. Native files are src/pd/{backoff,backoff_tests,opt_tests,retry}.rs,
complete package inventory/ExecPlans and Go oracle input/output. TiDB integration
updates the maintained vendor copy, sync log and audit/plan receipts.
