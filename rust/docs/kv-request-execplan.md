# Go-shaped kv request seam (ExecPlan)

## Purpose

`tidb-kv` (Go `pkg/kv`) still depends on `tidb-distsql` and `tidb-expr` because the storage seam `TableStorage` carries the coprocessor request un-serialized (`open_remote_scan(&PushdownScanRequest)` with `conditions: Vec<Expression>` and the statement context; `coprocessor_client() -> PushdownScanner`). In Go the client comes from the storage (`kv.Storage.GetClient()`, `pkg/kv/kv.go:874`; even the session-less DDL reorg uses `store.GetClient()`, `pkg/ddl/reorg.go:741`), and what crosses the seam is `kv.Request{Data}` -- a DAG the executor built and encoded (`table_reader.go:517`). So the client stays on the storage; the SERIALIZATION moves up into the executor. Today the lowering runs inside tidb-exec's `CopScanSource::open` (`cop_scan.rs:217-1000`, `.set_dag_request(..., plan.dag.encode_to_vec())` at :989). Most of Go `pkg/kv` already lives in `tidb-txnkv` (`Request` with `data`, `Priority`, `ReplicaReadType`, `Client`); checksum (`tidb-executor/src/checksum.rs`) is already Go-shaped and is the template.

## Steps (each compiles)

- [x] 0 `CancelHandle` into tidb-txnkv (distsql re-exports); `tidb_distsql::Priority` = `tidb_mysql::Priority` (Go `mysql.PriorityEnum`), `kv_priority` to its only user; tidb-variable uses `tidb_txnkv::ReplicaReadType` and drops tidb-distsql.
  Done: `CancelHandle` in `txnkv/rpc/call_context.rs`; `kv_priority` now `tidb_executor::remote_scan::kv_priority`.
- [x] 1 Go kv client contracts into tidb-txnkv: `TransportRequest`, `KvRequestMetadata`, `QueryResultSubset`, `ResponseRuntimeStats`, the core of `QueryResponse`; object-safe `Client::send` / `Response::next`; `impl kv::Client` in tidb-exec over the transport factory; checksum sends through it (Go `distsql.Checksum`).
  Done: `txnkv/{kv_request,kv_response}.rs`; `QueryResponse: tidb_txnkv::Response`; region-task splitting stays in distsql as `RegionTaskRequest`; `tidb_exec::cop_client::CopClient`; `tidb_distsql::{checksum, send_request}`.
- [x] 2 Seam primitives: `TableStorage::{start_ts, client, mpp_client}` beside `mem_buffer_snapshot`; `ClusterTableStorage` stores the client (attached in `open_storage_session` and the smoke binary); `coprocessor_client` replaced.
  Done: `start_ts`/`client` on the seam, `ClusterSessionFactory::with_kv_client`, checksum reads `table.store.client()`. Deferred: `mpp_client` (kv `MppClient` is not object-safe yet; step 4b). `TableStorage::coprocessor_client` and `KvTable::coprocessor_client` are deleted.
- [x] 3 TiKV lowering into the executor: `dag_request.rs`, `wide_scan_selection.rs`, the lowering half of `CopScanSource::open`; encodes and selects via the client; lowering refusal still falls back to the local scan.
  Done: `tidb_executor::cop_reader::open_cop_scan(&dyn kv::Client, &PushdownScanRequest)` (Go `buildResp` -> `distsql.SelectWithRuntimeStats` -> `dctx.Client.Send`), over `tidb_distsql::select_with_runtime_stats_over_client`; `scan_column`, `scan_receipt` and the lowering tests moved with it. `ClusterTableStorage::open_remote_scan` sends TiKV reads through its `client` and TiFlash reads through `with_tiflash_mpp` (the only `PushdownScanner` left: `TiFlashMppScanSource`, step 4); `CopScanSource` and `tidb-exec/src/cop_scan.rs` are deleted, and nodes / the smoke binary attach the client plus MPP only (`ClusterSessionFactory::with_tiflash_mpp`). tidb-exec's `tests/cop_scan_*` drive `open_cop_scan` over `CopClient`.
  Executor tests: `remote_scan.rs`'s `FakeCoprocessor` (which evaluated `PushdownScanRequest`s itself) is now `FakeRegion`, a `kv::Client` that runs the encoded DAG on unistore's cophandler over the committed snapshot (Go's executor tests on mockstore). Flags, keep-order and output offsets are read off the wire; read estimates (which never cross the wire) from a `#[cfg(test)]` request recorder on `ClusterTableStorage`; aggregate "wire" counts read the region's matched rows. Two tests of the old backend contract had no Go equivalent and were replaced: a backend may no longer "lower none of the predicate" (the real stream reports `predicates_applied`, and the readers then skip the local re-filter, as Go trusts TiKV), and a region refusal is the statement's error (`a_region_other_error_is_the_statements_error`), not a local fallback. Index requests, which the old fake refused into the local path, are now answered by the region.
  Deferred to step 5: lowering once per READER (Go `e.dagPB`) at the four `table_scan.rs` call sites instead of once per `open_remote_scan`; until then a process-wide one-entry `SELECTION_CACHE` (formerly per node) keeps a lookup's repeated windows from re-encoding a large `IN` list.
- [x] 4 TiFlash MPP: fragment lowering to the executor (Go `fragment.go` / `mpp_gather.go`), dispatch as `impl kv::MppClient` (keep the TiFlash refusal-by-name rule).
  - [x] 4a The plan half of Go `localMppCoordinator`: `tidb_executor::mpp_coordinator::{check_mpp_request, mpp_task_metadata, root_fragment_dag}` (refusal by name, the gather's task metas, `appendMPPDispatchReq`'s root DAG); `TiFlashMppScanSource` calls them, and is now itself the storage's TiFlash `PushdownScanner`.
  - [x] 4b The store half as Go `kv.MPPClient`: `tidb_txnkv::MppClient` is object-safe with concrete types (`construct_mpp_tasks` / `dispatch_mpp_task` / `establish_mpp_conns`; `MppContext` is Go's `ctx` plus the statement tracker, implemented by `StatementMemory`; `MppError`; `MppStoreTask`; `MppStreamResponse` with the packet hand-off). `tidb_exec::mpp_client::TiFlashMppClient` implements it (the module was `tiflash_mpp_scan`); `TableStorage::mpp_client()` is Go `GetMPPClient()` (`ClusterTableStorage::with_mpp_client`, `ClusterSessionFactory::with_mpp_client`). The coordinator -- dispatch loop, `MppTaskResponses`, `MppRecoveryResponse` (Go `mppErrRecovery`), `MppRowStream` -- is `tidb_executor::mpp_coordinator::open_mpp_scan`, with its task-meta and recovery tests; the socket tests stay with the client. `PushdownScanner` is deleted. Deviations: the dispatch's schema version is the node's catalog watch, read by the client per dispatch (Go's coordinator passes `is.SchemaMetaVersion()`; the session catalog's version is a mutation counter), so a recovery re-dispatch reads the then-current version; `CancelMPPTasks`, `CheckVisibility` and `GetMPPStoreCount` are not on the trait (cancel is the stream's close; the other two have no caller); the dispatch policy is parsed for classic TiFlash too (the session variable is validated, so an unparsable value cannot reach it).
- [x] 5 The storage seam names no request: `TableStorage::open_remote_scan` is gone; the readers call `tidb_executor::remote_scan::open_remote_scan(store, request)`, which takes the staged slice from `mem_buffer_snapshot` (an empty buffered value is Go's tombstone), reads at `start_ts()`, and sends through `client()` / `mpp_client()`. `remote_scan`'s request and stream types moved into the executor (`remote_scan/request.rs`); tidb-kv no longer depends on tidb-distsql, tidb-expr, tidb-chunk or tidb-ast (`mem_quota` takes `CancelHandle` from tidb-txnkv). A truncated cluster handle answers no client, so its reads fall to `iter`, which refuses the handle as before.
  Tests: every request-level store became a `kv.Client` fake asserting on the DAG and the `kv.Request` (`tidb_executor::test_region`: `SentRequest` decodes the DAG, ranges, row-count hints and, through the closest-replica adjuster, a reader's network estimate; `TestRegion` / `run_dag` answer on unistore; `canned_rows` answers fixed rows). Coverage that changed: a store can no longer refuse a request or report a Selection it dropped, so `index_selection_maps_hidden_handle_slots...` keeps only its applied arm and the partition test only its failing-send arm (both noted in place); the estimate tests assert whole bytes through the adjuster under a one-byte threshold, and the index/table width relation as "twice, up to rounding"; the index-join failure matrix compares the error's code and message (the wire does not carry Go's class); table-side lookups the old fakes refused into point gets are now remote, so the index-join test counts gets plus table requests.
  Remaining (perf, not shape): lowering once per READER (Go `e.dagPB`) instead of once per `open_remote_scan`; until then the process-wide one-entry `SELECTION_CACHE` keeps a lookup's windows from re-encoding a large `IN` list.
- [x] 6 tidb-variable no longer imports tidb-domain. `tidb_variable::GlobalVarAccessor` is Go's `variable.GlobalVarAccessor` (plus the typed reads Go serves from `vardef` atomics); `SessionVars` holds it as `Option<Arc<dyn GlobalVarAccessor>>`, nil until the session installs one, as Go's `NewSessionVars` leaves it and `createSession` sets it (`Session::new` installs a fresh node accessor; a factory's `attach_globals` its shared one). `GlobalSysvars` and its cache rebuild moved to `tidb_domain::global_sysvars` (Go's session-over-domain accessor), with `SessionVars`'s and the accessor's tests; tidb-variable keeps the SetGlobal hooks' shared pieces (`ResolvedGlobals`, `PdRegionPolicy`, `ExternalTimestampProvider`, `SET_GLOBAL_RESOURCE_CONTROL`, `global_get_hook`) and Go's `MockGlobalAccessor`. tidb-variable dropped tidb-domain, tidb-stmtsummary and tidb-tikvutil.
- [ ] Follow-up (Go-faithful, perf): hand the node's client to the DDL-worker and other storages that read with local scans today (`worker.rs` storages, `cluster_ddl.rs`, `cluster_table_storage.rs`, `cluster_session.rs`).
