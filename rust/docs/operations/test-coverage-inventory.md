## How to read this

`AGENTS.md` non-negotiable 6 makes a package claim include **every** original
test artifact. Production code ported without its tests is a partial port. This
file measures that gap. It is deliberately pessimistic about its own evidence:

| Evidence | Meaning | Strength |
| --- | --- | --- |
| `NAME-EXACT` | a Rust test's name normalizes to the Go test's name | WEAK. Same name is not same assertion. |
| `NAME-FUZZY` | one normalized name contains the other, or every word of the Go name appears in the Rust name | VERY WEAK. False positives on short names; catches the common case where a port was renamed to a sentence (`TestUnionIterErrors` -> `test_union_iter_source_error_identity_order_and_close`). |
| `REFERENCED` | the Go test name appears in Rust source/doc text but no test carries it | WEAK-NEGATIVE. Usually a citation, not a port. |
| `NONE` | no name, no citation | STRONG NEGATIVE. Treat as uncovered. |

**A high match ratio here does not mean a package is covered.** Only the `NONE`
column is trustworthy, and it is trustworthy in one direction: those Go tests
have no Rust counterpart under any name. Rows above the line are candidates for
a human behavior check, not evidence of parity.

Go tests counted: top-level `func TestXxx(t *testing.T)` and testify suite
methods `func (s *Suite) TestXxx(...)`. Table-driven subtests are *not* counted
as separate units -- they inflate both sides and are not separately addressable
in Rust. Benchmarks and fuzz targets are out of scope. Consequence, and the
largest systematic bias here: a Go test with a 200-row table counts once, so a
Rust test porting one of its rows matches at full credit. Coverage is therefore
**overstated** wherever Go used a table -- which is most of `pkg/types` and
`pkg/parser`.
