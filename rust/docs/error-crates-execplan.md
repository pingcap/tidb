# Go-shaped error crates (ExecPlan)

## Purpose

`tidb-dbterror` (created by the executor split) holds Rust-invented error enums pushed to the bottom of the crate graph only to satisfy the orphan rule. Go keeps `pkg/util/dbterror` to error-class prototypes (imports errno, parser/mysql, terror only), kv errors in `pkg/kv/error.go`, table errors in `pkg/table/table.go`, and passes plain `error` values upward (`terror.ToSQLError` at the wire). The result in Rust: the bottom crate depends on tidb-expr, tidb-variable (which depends on distsql and domain) and tidb-txnkv, so `tidb-kv` reaches distsql through it. This plan empties `tidb-dbterror` into Go's homes without changing any error code, state, message or identity.

| `memory_exceed_for_query` | `SQLKiller.HandleSignal` | `tidb_util::sqlkiller` |
| `var.rs` | `sessionctx/variable` | deleted |

Upper crates import through `tidb_executor::` paths, so moves need few edits there.

## Must not change

- The memory-exceeded identity (rendered with identity `None` today though Go prints `[executor:8175]`): a separate fix with its own test.
- `planner_bridge.rs` dispatches on `DriverError::Exec(ExecError::Eval)`: lower crates keep eval errors typed.
- `From<KvTableError> for ExecError` formats `{other:?}` into the message: keep variant names.
- `StorageError::Retryable` -> `Txn(RegionUnavailable)`, other non-SQL storage errors -> `Internal(to_string())`, verbatim.
- Before deleting any variant: `assert_eq!(DriverError::X(..).to_mysql_error(), helper(..))` (code, state, message, identity).

## Remaining kv inversion (separate)

`tidb-kv` still uses distsql's `CancelHandle`, `Priority`, `CopResponseSink`, `TransportRequest` and `tidb-expr`, because `TableStorage::open_remote_scan` carries the coprocessor request; Go's `kv.Request` carries the serialized DAG and `DistSQLContext.Client` the client. `tidb-variable` depends on distsql only for `ReplicaReadType` and on domain for `sysvar_cache`.
