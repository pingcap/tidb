# One Compile path on the cluster node (ExecPlan)

## Purpose

Go runs every statement as `ExecuteStmt` -> staleness check -> `Compile` (preprocess, `PlanBuilder.Build` with its visit infos and plan-time errors) -> `ExecStmt` -> `executorBuilder` by plan kind; the cluster-specific work (DDL jobs, account writes, global variables, statistics) happens inside the executors. The Rust cluster node instead ROUTES statements by the stored state they change (`schema_route` / `StatementRoute`, `tidb-session/src/domain/cluster_session_node/mod.rs`) before any plan is built, and only `Ordinary` statements reach the session's Compile. That duplicates Go checks (`schema_shape_refusal` repeats OPTIMIZE's 8200; DDL privileges are checked three times; ANALYZE and stats twice) and reorders them against Go's implicit commit. Stage 3 of `top-down-structure-execplan.md` names this direction; this plan is its concrete form.

## Divergences this removes (each gets a regression test that fails first)

- Accounts commit BEFORE the privilege check: a denied `CREATE USER` commits the user's transaction (Go: Compile's visit infos first, then `GrantExec`/`SimpleExec.autoNewTxn`). Verified correction: Go checks CREATE USER's (and ALTER/DROP USER's) privileges in the executor after `autoNewTxn` (`simple.go:1053`), so that denial does commit; the divergence is the statements with planner visit infos (GRANT, REVOKE, GRANT/REVOKE ROLE, RENAME USER).
- `SET PASSWORD` / `SET DEFAULT ROLE` commit; Go's `autoNewTxn` (`simple.go:3564`) does not list them.
- Executor-time DDL refusals (partition-spec and STATS_PERSISTENT 8200, LOCK TABLES checks, CREATE VIEW body resolution, target prechecks, lowering refusals) run before the implicit commit: Go's `BEGIN; INSERT; ALTER TABLE t CHECK PARTITION p0` commits the INSERT then answers 8200.
- REPAIR TABLE's 8215 exists only in `schema_shape_refusal`; Go raises it in the preprocessor (`preprocess.go:1407`).
- The staleness check runs after lowering in the DDL route (Go: before Compile, `session.go:2485`).

## Target structure

- `Session::compile(stmt) -> Compiled { plan, ctx }` for every statement: staleness, `validate_ddl_preprocess` (+ REPAIR MODE in `tidb_planner::preprocess::check_ddl_grammar`), `build_statement_plan`, `check_visit_infos`. The node's `compile` calls it once and derives its `CompiledStatement` from the `Plan` variant.
- One no-delay door on the store session (`run_no_delay(plan)`, outside the autocommit replay loop) wrapping `observe_routed_write`.
- `Session::execute_plan` arms: `Plan::Ddl` -> `ddl_exec` (`ddl_exec.rs`; after Go's `NewTxnInStmt` the target checks, lowering, `run_ddl_statement`); `Plan::Simple` account arms -> `new_txn_in_stmt` only for Go's `autoNewTxn` list + GRANT/REVOKE, then the account writer; `Plan::Set` -> SetExecutor with GLOBAL writes through the sysvar service; `Plan::Analyze` and the stats plans -> their services.
- `DomainServices` (`DdlService`, account, sysvar, analyze, stats services) on `Session`, installed in `attach_connection`; `None` on an in-process session.
- `Session::new_txn_in_stmt(&mut dyn TxnManagerOps)` with the store session's `StoreTxnOps` (fallback: the node commits between compile and execute keyed on `ddl_preserves_transaction`).
