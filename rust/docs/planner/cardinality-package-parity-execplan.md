# Complete TiDB Go Cardinality Package Parity

This ExecPlan is a living document. Keep `Progress`, `Surprises & Discoveries`, `Decision Log`, and `Outcomes & Retrospective` current as the package is implemented and validated.

Reference: repository-root `PLANS.md`. The Rust implementation may span multiple crates, but the completion unit is the entire upstream Go package `pkg/planner/cardinality`, including its production sources, tests, fixtures, build target, and validation requirements.

## Purpose / Big Picture

Rust planning must estimate rows, selectivity, distinct values, and row sizes the same way as TiDB Go master for the same statistics and session settings. This changes optimizer choices and estimated work for SQL workloads such as sysbench, TPC-C, TPC-H, and YCSB. Users can observe parity through matching estimates and plan choices for the Go package's original inputs and integration queries. No Rust-only estimate behavior is part of the target.
