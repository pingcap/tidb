## Purpose / Big Picture

Phase 1 needs a real crate boundary whose first APIs are complete translations of TiDB's KV contracts, not another in-memory executor approximation and not a hollow client skeleton. After this slice, `tidb-txnkv` owns byte-ordered `Key`, half-open `KeyRange`, and ordered `Version` primitives translated from `pkg/kv/key.go` and `pkg/kv/version.go`. A physically isolated transaction test package translates every representable source row from `TestPartialNext`, `TestIsPoint`, and `TestVersion`. The workspace still makes no claim about RPC, MVCC, locks, retries, commits, or a real TiKV client.

The observable proof is that both new manifests test independently before they are admitted to the root workspace, the codec-dependent `TestPartialNext` bytes are generated by the Go implementation and checked into the test package with a reproducible command, and strict Clippy plus formatting pass without unsafe code.

## Surprises & Discoveries

- Observation: `Key::PrefixNext` is not `Key::Next`. It increments the rightmost non-`0xff` byte and leaves overflowed suffix bytes as zero; empty and all-`0xff` keys instead append zero to the original bytes.
  Evidence: `pkg/kv/key.go:42-68`; `TestPartialNext` depends on this distinction.
- Observation: `KeyRange.IsPoint` accepts two distinct half-open point forms: `end == start.Next()` when lengths differ and `end == start.PrefixNext()` when lengths match. An all-`0xff` start cannot be a same-length point range.
  Evidence: `pkg/kv/key.go:115-147` and every row in `pkg/kv/key_test.go:63-113`.
- Observation: most of `key.go` and `key_test.go` is deliberately outside this foundation. Handle decoding depends on TiDB codec/types; memory usage relies on Go slice layout and unsafe casts; retry classification lives in a different error contract.
  Evidence: `pkg/kv/key.go:149-764` and `pkg/kv/key_test.go:115-479`.
- Observation: `version_test.go` colocates unrelated MPP and exchange-compression tests. Only `TestVersion` exercises `pkg/kv/version.go`'s primitive.
  Evidence: `pkg/kv/version_test.go:25-98`.
- Observation: after the bounded key/version primitives, no remaining source test can be moved into `tidb-txnkv` without crossing an unavailable production boundary or violating crate ownership.
  Evidence: `TestBasicFunc` depends on `dbterror`/MySQL error identity; all Handle/map tests depend on the complete datum codec or Go-specific memory accounting; `TestKeyRangeDefinition` asserts unsafe kvproto layout aliasing; the two sibling version tests belong to MPP/session protobuf consumers.

## Decision Log

- Decision: represent `Key` as an owning Rust newtype over `Vec<u8>` with lexicographic `Ord`, explicit byte access/conversion, source-equivalent next/prefix-next/prefix operations, deep `Clone`, and lowercase hexadecimal `Display`.
  Rationale: ownership makes Go's clone contract structural, standard `Ord` is the exact Rust form of `bytes.Compare`, and a newtype prevents arbitrary string semantics from entering storage keys.
  Date/Author: 2026-07-15 / Codex.
- Decision: implement `KeyRange::is_point` from the source branch structure rather than by allocating both candidate successor keys.
  Rationale: this preserves the exact half-open contract and edge cases while retaining Go's allocation-free behavior without its unsafe layout hack.
  Date/Author: 2026-07-15 / Codex.
- Decision: represent `Version` as an ordered `u64` newtype with `MIN_VERSION`, `MAX_VERSION`, `Version::new`, and a value accessor; do not add a provider/client trait with no implementation.
  Rationale: these are the complete semantics in `version.go` used by `TestVersion`. An unused provider trait would be architecture-shaped scaffolding rather than delivered behavior.
  Date/Author: 2026-07-15 / Codex.
- Decision: keep both new manifests temporarily standalone with explicit package metadata and local lint policy.
  Rationale: Cargo refuses manifest-path testing for a package below a workspace unless it is a member or declares its own workspace. The root manifest was explicitly owned by the integrating agent, so each new package temporarily declared `[workspace]`. This decision is now fulfilled: root removed those stanzas, adopted workspace inheritance, and added both members atomically before the second-wave audit.
  Date/Author: 2026-07-15 / Codex.
- Decision: classify the second-wave rows as explicitly blocked instead of implementing test-only facsimiles.
  Rationale: a Go-generated fixture is valid evidence for fixed codec input bytes, but it cannot replace a production decoder, typed error identity, safe protobuf conversion, or real MPP/session consumer. Preserving those ownership boundaries prevents false `tidb-txnkv` maturity while ensuring no upstream test disappears from the queue.
  Date/Author: 2026-07-15 / Codex.

## Interfaces and Dependencies

The production package has no dependencies outside `std` and exposes:

    pub struct Key(Vec<u8>);
    impl Key {
        pub fn from_bytes(bytes: impl Into<Vec<u8>>) -> Self;
        pub fn as_bytes(&self) -> &[u8];
        pub fn into_bytes(self) -> Vec<u8>;
        pub fn next(&self) -> Self;
        pub fn prefix_next(&self) -> Self;
        pub fn compare(&self, another: &Self) -> Ordering;
        pub fn has_prefix(&self, prefix: &Self) -> bool;
    }
    impl Ord for Key;           // unsigned lexicographic byte ordering
    impl Clone for Key;         // deep because the Vec is owned
    impl Display for Key;       // lowercase hexadecimal

    pub struct KeyRange {
        pub start_key: Key,
        pub end_key: Key,
    }
    impl KeyRange {
        pub fn new(start_key: Key, end_key: Key) -> Self;
        pub fn is_point(&self) -> bool;
    }

    pub struct Version(u64);
    pub const MIN_VERSION: Version;
    pub const MAX_VERSION: Version;
    impl Version {
        pub const fn new(value: u64) -> Self;
        pub const fn value(self) -> u64;
    }
    impl Ord for Version;
