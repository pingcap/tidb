## `col -> path` / `col ->> path` -- JSON extraction, DESUGARS at parse
## time to `JSON_EXTRACT(col, path)` / `JSON_UNQUOTE(JSON_EXTRACT(col,
## path))`. Real TiDB's own grammar has no dedicated AST node for this
## operator at all (pkg/parser/expr_parser.go's `case jss, juss:` builds
## a plain FuncCallExpr) -- matches the SAME "operator desugars to a
## function-call AST shape" precedent date_expr +/- INTERVAL already
## established. ONLY valid when the left operand is a BARE COLUMN
## reference (confirmed via godump restore: `(a+b)->'$.x'` is a genuine
## ParseError). Needs NO new evaluation code: JSON_EXTRACT/JSON_UNQUOTE
## are unrecognized function names to tidb_expr::eval_func's own existing
## wildcard, already Unsupported (this crate has no JSON value domain
## yet).
##

## AS-OF-style two-word merge). Relies on the SAME generic eval_in
## wildcard Expr::MatchAgainst already uses -- Unsupported,
